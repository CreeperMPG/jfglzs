# jfglzsn 行为分析

> 所属家族：机房管理助手（jfglzs13.4）· 组件定位：**核心调度（策略执行引擎）**
> 分析基于反混淆还原后的代码，非恶意样本运行观察。

## 一、程序概览

`jfglzsn.exe` 是家族里的**策略执行引擎**：一个没有可见界面的 WinForms 宿主，加载后建立 14 个 `System.Windows.Forms.Timer` 与 1 个 WMI 进程创建监视器，然后把「禁 U 盘、关防火墙、封网、猎杀进程、守护电子教室、锁屏、强制关机」这些动作按定时器分主题循环执行。

它不提供任何管理界面，也不做整体配置——配置由 `set.exe` 写进注册表，本程序只负责**读取开关并执行**，同时自己承担「守护服务、重生副本、校验自身配置被改」的自保职责。

| 项 | 值 | 含义 |
| --- | --- | --- |
| 程序集名 | `jfglzsn` | 输出 `jfglzsn.exe` |
| 输出类型 | `WinExe` | 有消息循环的 GUI 宿主（尽管无可见界面） |
| 目标框架 | .NET Framework `v4.5` | VB.NET 编译产物 |
| 入口点 | `jfglzsn.Internal.CallbackEvent.GetCallback` | `[STAThread]`，即进程 `Main` |
| 主窗体 | `WindowsApplication1.Form1` | 由 `OnCreateMainForm` 懒加载 |
| 程序集版本 | `10.2.0.0` | 开发期遗留值，与对外版本 13.4 不一致 |
| 程序集 GUID | `867bd42f-1e95-4fbd-9aa5-f814e85d5036` | 无强名称签名 |
| 清单权限 | `requestedExecutionLevel level="requireAdministrator"` | 启动即索要管理员权限 |
| 单实例策略 | `IsSingleInstance = false` | **允许并存多份**，配合随机进程名 |
| 反分析标记 | `[SuppressIldasm]` | 阻止 `ildasm` 打开；程序集元数据（Title/Company/Product）全为空串 |

代码分两层，界限清楚：

- **业务层**：`WindowsApplication1.Form1` ~ `Form4`。真正的恶意行为 100% 在这一层，其中 `Form1` 是唯一的执行体。
- **壳残骸层**：`Internal.ListSetter`（自实现 MD5、AES、字符串解密、IL 自补丁）、`Internal.PrototypeSetter`（内嵌程序集解析）、`Internal.MethodSetter`（IntelliLock 未注册提示）、`Internal.RuleSetter` / `ILLicenseModule` / `Internal.EventEvent` / `Internal.ProductEvent`（空属性类、授权桩、模板替身）。这些保护能力**装配完好但无调用点**——解壳阶段已把调用点换成明文，它们如今主要是「样本用了什么壳」的证据。

`Internal.ThreadEvent` 是系统操作底座（6 个注册表封装 + SHA256 摘要），`Internal.SetterEvent` 是 VB 模板的 `My` 命名空间聚合（所有跨窗体调用都经 `SetterEvent.ComputeCallback.FormN` 取得单例），`Internal.CallbackEvent` 只做启动配置。

## 二、界面与交互流程

### 2.1 主窗体：存在但不可见

`Form1` 的构造里完成字段初值、挂 `Load` / `FormClosing`，再调 `初始化组件()` 建 14 个定时器。窗体本身设成 `FormBorderStyle.None`、`ShowInTaskbar = false`、`WindowState = Minimized`，`Load` 第一句就是 `Hide()`。学生在桌面、任务栏、Alt+Tab 里都看不到它。

启动链：

`GetCallback` → `SetterEvent.CollectCallback.Run` → `OnCreateMainForm`（取 `My.Forms.Form1`）→ `Form1()` → `窗体加载初始化` → `Timer_main` 每 6 秒推进一次启动阶段。

### 2.2 三个展示/惩罚窗体

| 窗体 | 外观 | 可用操作 | 关闭方式 |
| --- | --- | --- | --- |
| `Form3` | 常规边框、`TopMost`、1260×558、屏幕居中、`SystemColors.Highlight` 蓝底红字（宋体 15.75pt）、标题「警告」 | 无按钮、无输入框 | 没有 `FormClosing` 守卫，标题栏能关；但下一次监控 Tick（5~17 秒内）会重新 `Show()` |
| `Form2` | 最大化、无边框、`TopMost`、不进任务栏、1518×1092、蓝底 | 密码框 + 「确 定」+「重启电脑」 | `FormClosing` 无条件 `e.Cancel = true`，**关不掉** |
| `Form4` | 同 Form2 结构，1254×729，标题误写为 `Form2`（复制残留） | 同上（接受两套口令） | 仅当 `ThreadEvent.mapperEvent` 为真才拒绝关闭——该标志本工程内从未被置真 |

`Form2` / `Form4` 都由 1 秒定时器维持在场：每次 Tick 把窗口重新置顶，并用 `ClipCursor` 把鼠标光标锁进屏幕左上角 `{Left=0, Top=0, Right=800, Bottom=100}` 的窄带；累计 5 次后每次 Tick 追加 `Beep(2000, 500)`（2000 Hz、500 ms）。`Form1` 侧的 `Timer2`（1 秒）负责「`Form2` 不可见就重新 `Show()`」，这是惩罚界面「关不掉」的真正实现。

> **本版本 `Form4` 是死链**：`Timer4`（1 秒）建好后从未被 `Enabled`，全工程也没有第二处 `Form4.Show()`，所以锁屏窗体在这份样本里永远不会出现（除非外部代码手工触发）。`Form2` 才是实际在用的惩罚面。

### 2.3 交互流程

学生端没有任何正常入口，可触发的交互只有两类：

1. **被动接收**：违规时弹出 `Form3`（文字警告）或 `Form2`（密码门惩罚）。
2. **在惩罚窗上输入密码**：
   - `Form2`「确 定」：长度 ≥ 6 后计算 `SHA256(输入 + "bfdshgs")`，与 `HKCU\Software` 值 `n` 比对；不等则提示「密码不正确，请重新输入！」并清空输入框。
   - `Form4`「确 定」：同样算法，但接受 `HKCU\Software\n` 或 `HKCU\Software\jfglzs\n2` 任一（`n2` 是设计给锁屏窗的应急口令）。这条路径在本版本中因 `Form4` 未接线而走不到。
3. **「重启电脑」按钮**（两窗都有）：直接执行 `shutdown /r /f /t 0`，不提示、不给保存机会。

密码正确后进入退出流程：

- `Form2` → `PostCallback()`：循环杀掉随机名进程 → 枚举全部进程、杀掉「名字长度 ≥ 4 且每个字符 ASCII 都在 102~111（'f'~'o'）」的进程 → 写 `DisableCMD = 0` → `net stop zmserv` → 等 3 秒 → 杀 `zmserv` 进程 → `ClipCursor` 恢复整屏解除鼠标锁定 → `ProjectData.EndApp()`。
- `Form4` → `SortCallback()`：同上，但多一条「保留管控」逻辑——若 `DisableCMD` 原本为 `1`，临时置 `0` 停服务后再**置回 1**，退出后学生依旧没有 CMD。

> 那个 `'f'~'o'` 字符区间判据是**写错的意图**：作者本意应是识别某类程序，实际效果是「杀掉名字全由 f~o 组成的进程」，属于把同目录自身副本一并清掉的粗糙实现。

管理侧（老师）的操作只有「输密码 → 程序自己退出并恢复部分策略」，没有配置界面——配置入口在 `set.exe`。

## 三、核心行为

### 3.1 加载初始化（`Form1_Load`，13 步）

原版整段是 `On Error Resume Next`，还原后逐条 `try/catch`，任何一步失败都不阻断后续（尤其不能因为「杀 taskmgr 失败」而装不上 WMI 监听）。

| 步骤 | 动作 |
| --- | --- |
| ① | `Hide()` 隐藏主窗体 |
| ② | 用「月 × 日」做种生成 4 字母名（`97/98/101/99 + 余数`），写入 `ThreadEvent.m_AdapterEvent` / `_AdvisorEvent` |
| ③ | 再 `VBMath.Randomize` 一次，取 `Rnd()*100000*3+1` 逐位 `%10+105` 拼 5 字符名（字符集 `i`~`r`）覆盖上一步；`伪装安装目录 = C:\Program Files (x86)\ + Mid(名,2,4)` |
| ④ | 读 `HKCU\Software\jfglzs` 的 `dzjs` / `usb_jianche` / `shadu_jianche` / `cmd_jianche` |
| ⑤ | `dzjs` 按逗号拆表并决定监控模式：首项为 `other` 或空 → 0（不监控）；含 `\` → 2（路径状态机）；否则 → 1（按进程名） |
| ⑥ | 填进程名黑名单 28 项、关键词黑名单 78 项，`关键词表上界 = 78` |
| ⑦ | **立刻杀一次 `taskmgr`**（`GetProcessesByName("taskmgr")[0].Kill()`） |
| ⑧ | 起 WMI `__InstanceCreationEvent`（1 秒轮询、`TargetInstance ISA 'Win32_Process'`）→ `EventArrived += 新进程拦截` → `Start()` |
| ⑨ | 探测极域注册表分支：先读 `Wow6432Node\TopDomain\e-Learning Class\Student` 的 `ChannelId`/`AutoLogin`，读到非 0 → 分支 1；读到 0 则改读 32 位路径，读到非 0 → 分支 2。任一分支成立即开 `Timer_jiyu`；两处都是 0 则不监控 |
| ⑩ | 检查 `tdfilefilter` / `tdnetfilter`：不存在则不纳管；停了就 `Start()`，`Sleep(1000)` 后都在 `Running` 才置 `极域服务受管 = true` |
| ⑪ | 记录三份基线快照：口令摘要（`HKCU\Software\n`）、`Run\prozs`、`Run\jfglzsn`（64 位为空则查 `Wow6432Node`） |
| ⑫ | 读 `gaowei`（默认 2）与 `zhuye`（云端域名） |
| ⑬ | 杀软检测：`QQPCTray` / `360sd` / `360Tray` 任一在跑 → 弹「加载一个控件不能成功！…」；否则 `zhuye` 非空时 `Process.Start(<程序目录>\zy.exe)` |

### 3.2 分阶段启动时序

`Timer_main` 6 秒一跳，只在初期有意义，第 6 次后自己关掉：

| 计数 | 动作 |
| --- | --- |
| 每次 | 若 hosts 尚未接管且域名非空 → 拉一次 `http://<zhuye>/hmd_net.txt` |
| 1 | 三个快照都非空才开 `Timer_qdx`（口令/自启动项，3 秒）；`usb_jianche == "on"` 才开 `Timer_usb`（5 秒） |
| 4 | 开 `Timer_fhq`（防火墙，13 秒）与 `Timer1`（服务守护，6 秒） |
| 5 | 开 `Timer_wangluo`（网络，17 秒）；电子教室进程不在则从 `<程序路径>2` 复制回来并 `Process.Start` |
| 6 | 再查电子教室（缺失则开 `Timer_dzjs`，16 秒）；把 hosts 备份为 `hosts2`；需要接管则开 `Timer_updatehosts`（30 秒）；关掉 `Timer_main` |

14 个定时器中 `Timer_jcm`(5 s) / `Timer3`(1 s) / `Timer_route`(11 s) 没有挂事件处理器，是空转残留。

### 3.3 进程猎杀（核心）

WMI 回调 `新进程拦截` 对**每一个新启动的进程**做两轮匹配：

1. 取 `TargetInstance` 的 `ProcessId` / `Name`，`Process.GetProcessById` 拿 `MainModule.FileName`，再拼 `ProductName + FileDescription` 作为描述文本。
2. **第一轮（进程名）**：`InStr("|" + UCase(进程名), UCase(表项))`。起点受 `shadu_jianche` 控制：为 `off` 时从第 2 项起（放行火绒 `HipsTray.exe`），否则从第 1 项起。
3. **第二轮（文件属性）**：把描述文本与表项做 `InStr`（区分大小写）。起点受 `cmd_jianche` 控制：`off` 时从第 4 项起。
4. 按命中下标分段处置：

| 命中来源 | 下标区间 | 处置 |
| --- | --- | --- |
| 进程名 | 1~10（360 / QQ 管家 / 火绒托盘等杀软） | 只弹 `Form2` 杀软警告，**不杀进程**（让老师看清哪台机器装了杀软） |
| 进程名 | 11~16（进程工具 / 任务管理器 / 虚拟桌面 / 扫雷纸牌） | `Kill()` + `Form3` |
| 进程名 | 17~21（WinRAR / 7z / Bandizip / 360 压缩） | `解压拦截开关 != 1` 才 `Kill()` + `Form3` |
| 进程名 | ≥ 22（掌控课堂 / 极域 / 课堂狂欢器 / 吾爱破解） | `Kill()` + `Form3` + `WaitForExit(1000)` + **`FileSystem.Kill(程序路径)` 删文件** |
| 关键词 | ≤ 4 | `Sleep(2000)` 后 `Kill()` |
| 关键词 | 5、6 | 先 `Form3`，再 `Sleep(2000)`，再 `Kill()` |
| 关键词 | 7~50 | `Kill()`；命中号 ≠ 43 时补弹 `Form3` |
| 关键词 | > 50 | `Kill()` + `Form3` + `WaitForExit(1000)` + **删文件** |

被猎杀对象横跨五类：任务管理器与系统工具（`taskmgr`、注册表编辑器、MMC）、进程/内核工具（PC Hunter、IceSword、Process Hacker、Procmon、OpenArk、PowerTool…）、虚拟桌面类、解压软件、以及**极域破解工具**（极域杀手、KillControl、FuckMythware、再见极域、Hello Teacher 等）。其中最后一类（下标 ≥ 22）会连程序文件一起删掉。

### 3.4 系统策略篡改

| 目标 | 写入值 | 效果 |
| --- | --- | --- |
| `HKLM\SYSTEM\CurrentControlSet\Services\usbstor` 及 `ControlSet001~003` | `Start = 4`（DWord） | **禁用 USB 存储**；只要读回 3 就强制改回 4 并弹「你修改注册表企图使用U盘！请重新启动电脑。」 |
| `HKLM\SYSTEM\…\SharedAccess\Parameters\FirewallPolicy\StandardProfile` / `PublicProfile` | `EnableFirewall = 0` | 关防火墙；同时执行 `netsh advfirewall set allprofiles state off` |
| `HKCU\Software\Policies\Microsoft\Windows\System` | `DisableCMD = 0` / `1` | 放开 / 禁用命令提示符（多处调用，Form4 退出时会恢复为 1） |
| `HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Image File Execution Options\route.exe` | `DeleteSubKey` | 清掉学生对 `route.exe` 的 IFEO 劫持，为后面的加路由扫路 |

防火墙监控的判断有个细节：读回的 `EnableFirewall`（DWORD）是拿**字符串 `"1"`** 做 VB 弱类型比较的，不能改写成 `== 1`。

### 3.5 封网（危害最大的一环）

`下载并写入hosts黑名单(地址, 模式)` 的完整链路：

1. `IsPortOpen("www.baidu.com", 443, 2000)` 探活；不通就直接返回（下次心跳重试）。
2. `WebClient.DownloadFile` 把云端名单下载到硬编码路径 `c:\1.txt`；首行不含 `www.` 视为无效名单（防运营商劫持）。
3. 用三个中文标记切段：`视频网站：`、`产品名：`、`IP地址：`，各取「前一行 / 后一行」为段边界。
4. 读现有 hosts，收集已存在 `127.0.0.1 <域名>` 的域名集合用于去重。
5. **段 1**（开头 → `视频网站：` 前）：每行归一化成域名（去 `http://`、`https://`、路径、转小写），追加 `127.0.0.1 <域名>`。
6. **段 2**（`视频网站：` 后 → `产品名：` 前，仅当 `模式 == "off"`）：同样处理。
7. **段 3**（`产品名：` 后 → `IP地址：` 前）：**逐行写入关键词黑名单**，从 `关键词表上界 + 1` 开始往后接——这就是「服务端远程扩充猎杀列表」的通道。
8. 删 IFEO 键（见 3.4），然后 **段 4**（`IP地址：` 之后）：逐条 `route add <IP> mask 255.255.255.255 0.0.0.0 metric 1` 加**黑洞路由**。
9. 写回 hosts，`hosts已写入 = true`，把 hosts 属性置为 `ReadOnly | Hidden | System` 防止学生编辑。
10. `DisableCMD = 0`，`ipconfig /flushdns` 立即生效。

即：**域名层（hosts）+ IP 层（/32 黑洞路由）+ DNS 缓存刷新** 三层同时封禁，名单与目标全部由云端 `zhuye` 域控。

### 3.6 电子教室守护与强制关机

- 模式 0：关掉 `Timer_dzjs`，不监控。
- 模式 1：遍历 `dzjs` 拆出的进程表，逐个 `GetProcessesByName`，缺一个就弹 `Form2`「电子教室进程未找到或本地连接IP地址错误！请重新启动电脑。」
- 模式 2（配的是完整路径）：`CheckProcessStatus` 返回四态状态机——
  - `Running` → 挂起计数清零，若之前报过缺失就关掉 `Form3`；
  - `Suspended` / `NotResponding` → 挂起计数 +1；> 8 弹 `Form3`，> 10 升级 `Form2`「电子教室程序被暂停！」；
  - `NotFound` → 缺失计数 +1，缺文件先从 `<路径>2` 复制回来再 `Process.Start`；**缺失计数 ≥ 5 直接强制关机**。

强制关机的实现是内核级：`RtlAdjustPrivilege(19, 1, 0, ref 原状态)`（取 `SeShutdownPrivilege`）→ `NtShutdownSystem(2)`，随后叠加 `shutdown /s /f /t 0` 兜底。

### 3.7 服务守护与自我重生（`Timer1`，6 秒）

- **服务段**：`zmserv` 进程不在 → 缺 `zmserv.exe` 就从 `C:\windows\jf\zmserv.dat` 复制出来 → 放开 `DisableCMD` → `sc create zmserv binPath= <程序目录>\zmserv.exe start= auto` → `net start zmserv`。
- **副本段**：`ThreadEvent.m_AdapterEvent`（当日随机名）对应进程不在 → 拉起计数 +1，缺 `przs.exe` 就从 `C:\windows\jf\przs.dat` 复制出来并 `Process.Start`。
- **重生段**：拉起计数 ≥ 5 → 放开 CMD → `net stop zmserv` → `Sleep(3000)` → 重新 `sc create` + `net start` → `Process.Start(<程序目录>\jfglzsn.exe)` → 旧进程 `ProjectData.EndApp()` **自杀**。

### 3.8 自身配置防篡改

`Timer_qdx`（3 秒）做两件事：

1. 读 `HKCU\Software\n`，与启动时的口令摘要快照比较；不等就**强制写回快照值**并弹「你修改了助手的密码！」「现在强制恢复密码！」；累计 > 25 次升级成 `Form2` + 每秒复弹。
2. 读 `Run\prozs` / `Run\jfglzsn`（64 位为空则查 `Wow6432Node`），与快照不一致就无条件重写为 `<程序目录>\przs.exe` / `<程序目录>\jfglzsn.exe`。

即：**每 3 秒校验一次密码与自启动项，被改就立刻还原**。

### 3.9 能力但未接线（壳残留）

以下能力在代码中完整存在，工程内却没有任何调用点，属于解壳后的残骸：

| 位置 | 能力 |
| --- | --- |
| `ListSetter.运行时还原方法体` | `OpenProcess(0x38)` + `VirtualProtect` + `WriteProcessMemory` + `Marshal.WriteInt32`，从内嵌资源取补丁改写自身代码段（反脱壳/反篡改） |
| `ListSetter.解密字符串` | `OpenProcess(PROCESS_VM_READ)` + `ReadProcessMemory` 从自身 PE 映像按偏移取字符串密文，AES 解密并缓存 |
| `ListSetter.AES加密/解密` | 硬编码 AES-256 Key + 口令派生 IV（`MD5(UTF16LE(口令))`），原本用于生成注册码/加密配置 |
| `ListSetter.自实现MD5` | 手写 MD5 全轮，用于系统 FIPS 策略禁用 MD5 时兜底 |
| `PrototypeSetter.解析程序集回调` | 内嵌程序集按 `"b0494a1f-4bd3-" + Base64(MD5(UTF16LE(简单名)))` 取名，优先内存 `Assembly.Load`，失败则落盘 `%TEMP%\<资源名>\<简单名>.dll` 再 `Assembly.LoadFile` |
| `MethodSetter.显示未注册提示` | 弹 `This assembly is protected by an unregistered version of "IntelliLock"!`（标题 `www.eziriz.com`） |
| `Form1` 中的 12 个 P/Invoke | `NtSuspendProcess` / `NtResumeProcess` / `BlockInput` / `keybd_event` / `SetForegroundWindow` / `GetWindowTextA` / `GetDriveTypeA` 等——除 `RtlAdjustPrivilege` 与 `NtShutdownSystem`（用于强制关机）外，其余声明均无调用点 |

## 四、与其他组件的关系

`jfglzsn` 处在「策略被下发 → 被执行 → 被守护」链条的中段，与家族其他 5 个组件通过**注册表 + 文件 + 进程名**这三条朴素通道耦合，没有进程间通信协议。

| 对端 | 关系 | 代码依据 |
| --- | --- | --- |
| `zmserv.exe`（看门狗服务） | **被守护对象与守护者互为因果**：jfglzsn 负责注册/启动/重启 `zmserv`；反过来 `zmserv` 每 5 秒检查「当日随机名进程」与 `jfglzsn` 是否都在，**连续 16 次（约 80 秒）都缺席就 `NtShutdownSystem` 强制关机**，让机器「杀不干净」 | `Form1.服务守护与自更新` 里的 `sc create zmserv … start= auto`；`zmserv\ProcessMonitorService.cs` 的 `监视周期检查` |
| `przs.exe`（主控驻留，随机名） | jfglzsn 每 6 秒确认它的存活，缺文件就从 `C:\windows\jf\przs.dat` 释放并拉起；`przs` 则每 3 秒反查 `jfglzsn`，缺了就复制 `C:\windows\jf\jfglzsn.dat` 重装成 `jfglzsn.exe` 再启动 | `Form1.服务守护与自更新` 第二段；`przs\Form1.Designer.cs` 的 `Timer1` |
| `jfglzsn.exe` 自身 | 拉起计数满 5 次时启动新副本并 `EndApp()` 让旧进程退出——不依赖外部，自己完成「更新」 | `Form1.服务守护与自更新` 第三段 |
| `set.exe`（管理端设置） | 上游配置源。本程序读的 `HKCU\Software\jfglzs` 下 `dzjs` / `usb_jianche` / `shadu_jianche` / `cmd_jianche` / `gaowei` / `zhuye`，以及 `HKCU\Software\n` 口令摘要，本工程内都不写入——只读不写（唯一例外是口令被篡改时回写快照） | `Form1.窗体加载初始化` 的第 ④⑪⑫ 步 |
| `about.exe` / `uninstall.exe` | 家族的「受控退出 / 卸载」通道（详见仓库 `README.md` 的组件清单）。家族约定：动 `jfglzsn` 之前必须先 `net stop zmserv`，否则触发上面的强制关机 | 家族文档层面；本工程内体现为 `Form2.PostCallback` / `Form4.SortCallback` 里 `net stop zmserv` 先于结束自身 |
| 极域电子教室 | **被保护对象**：`tdfilefilter` / `tdnetfilter` 两服务被强启并监控，`ChannelId` / `AutoLogin` 两个注册表参数被基线化并按 15 秒周期比对，进程被杀了从备份复制回来 | `Form1.极域监控`、`Form1.电子教室进程监控` |

共享资源一览：数据目录 `C:\windows\jf`（`zmserv.dat` / `przs.dat` / `jfglzsn.dat`）、注册表 `HKCU\Software\jfglzs`、`HKCU\Software\n`、`HKLM\…\Run` 的 `prozs` / `jfglzsn` 两个值、系统 `hosts` 与其备份 `hosts2`、服务名 `zmserv`。

## 五、持久化与配置

### 5.1 持久化手段

| 手段 | 落地 | 自我修复 |
| --- | --- | --- |
| Windows 服务 | `sc create zmserv binPath= <程序目录>\zmserv.exe start= auto` + `net start zmserv` | 每 6 秒检查进程，不在就重建服务 |
| 注册表自启动 | `HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Run\prozs` = `<程序目录>\przs.exe`；`…\Run\jfglzsn` = `<程序目录>\jfglzsn.exe` | 每 3 秒比对快照，不一致立刻重写 |
| 载荷落盘 | `C:\windows\jf\zmserv.dat` → `<程序目录>\zmserv.exe`；`C:\windows\jf\przs.dat` → `<程序目录>\przs.exe` | 文件丢失即从 `.dat` 重新释放 |
| 进程名伪装 | 以「月 × 日」为种推出 5 字符名（字符集 `i`~`r`），每天固定、可提前算出 | 供 `przs` / `zmserv` 互查使用 |
| hosts 固化 | 写完后置 `ReadOnly + Hidden + System` | 每次运行重新接管并备份 `hosts2` |
| 用户设置落盘 | `SaveMySettingsOnExit = true` + `My.Settings` 的 Shutdown 钩子 | 退出时写 `user.config`（本工程未定义设置项，内容极少，仅作「运行过」的取证痕迹） |

## 六、危害总结

| 维度 | 具体危害 | 严重度 |
| --- | --- | --- |
| **可用性破坏** | 连续 5 次救不回电子教室进程即内核级关机（`NtShutdownSystem` + `shutdown /s /f /t 0`）；惩罚窗「重启电脑」按钮零延迟强重启，不给保存机会 | 高 |
| **系统策略劫持** | 禁 USB 存储（4 处 ControlSet）、强关防火墙、禁 CMD、删 IFEO 键；`Form4` 的退出流程还会把 CMD 禁回去（该窗体本版本未接线） | 高 |
| **网络封锁** | hosts 写 `127.0.0.1` + `/32` 黑洞路由 + 刷新 DNS，三层封禁；hosts 设只读+隐藏+系统；名单与封禁目标完全由云端 `<zhuye>` 域控 | 高 |
| **数据破坏** | 对命中黑名单尾部（≥22 / >50）的进程：`Kill` → `WaitForExit` → `FileSystem.Kill(程序路径)` **直接删除程序文件** | 高 |
| **操作剥夺** | 全屏惩罚窗体 `Form2`：`TopMost` + 无边框 + 最大化 + 关不掉 + `ClipCursor` 把鼠标锁进 800×100 区域 + 5 次后持续 `Beep`（设计上还有 `Form4` 锁屏，本版本未接线） | 高 |
| **行为监控** | WMI 1 秒轮询记录每个新进程的 PID、映像名、完整路径与版本信息；每 15 秒读取极域参数、每 17 秒读取网卡 IP、每 3 秒读取注册表口令与自启动项 | 中高 |
| **持久化与自愈** | 服务 + 双 Run 键 + 随机名进程 + `.dat` 载荷释放；服务/副本/配置文件被删被改都会在秒级内被还原；满 5 次失败则重启自身新副本 | 高 |
| **反分析与对抗** | `[SuppressIldasm]`、元数据全空、随机进程名、隐藏窗体、壳层 IL 自补丁与字符串加密（当前已失活）；主动猎杀任务管理器、注册表编辑器、进程工具与极域破解工具 | 中高 |
| **权限滥用** | 清单要求 `requireAdministrator`，运行后具备关防火墙、改 `HKLM`、建服务、删文件、内核关机的完整能力 | 高 |

补充判断：

1. **本组件不能单独形成完整控制力**。它没有配置界面、不写策略开关，只读 `HKCU\Software\jfglzs` 并执行；即便配置为空，它照样会强关防火墙、加载即杀 `taskmgr`、按内置 28 + 78 项黑名单猎杀进程，并装好「服务 + Run 键」的自启链。破坏力的上限取决于 `set.exe` 写入的开关与云端 `hmd_net.txt` 名单，以及 `zmserv` / `przs` 构成的守护闭环。
2. **攻击者的意图与控制面对称**：黑名单里既有「反管控工具」（极域杀手、KillControl、PC Hunter、IceSword），也有「学生娱乐」（扫雷、纸牌、虚拟桌面、解压软件、视频网站 hosts 名单），说明目标是「让机房只剩电子教室可用」。
3. **清除时机的坑**：必须先 `net stop zmserv` 再结束 `jfglzsn`，否则 `zmserv` 会在约 80 秒内判定主程序缺席并强制关机；同时 `C:\windows\jf` 下的 `.dat` 与 `HKCU\Software\n` / `n2` 必须一并清理，否则重启后会被重新释放并接管。
4. **口令强度薄弱**：`SHA256(明文 + "bfdshgs")` 单轮、固定盐、无迭代，属于可离线爆破的形态；`n2` 作为备用口令的存在进一步说明「密码门」只是对学生的软约束，而非真正的安全边界。
