# set 行为分析

> 所属家族：机房管理助手（jfglzs13.4）· 组件定位：**管理端设置（策略下发入口）**
> 分析基于反混淆还原后的代码，非恶意样本运行观察。

## 一、程序概览

`set.exe` 是家族的「管理端」：管理员用密码进入后，在一个窗体上勾选 12 项限制，点「保存设置」就**一次性**把整机策略写死——注册表组策略、Windows 服务、开机自启、hosts、文件属性、浏览器入口全在这一下落地。它自身**不常驻、无定时器、无 WMI 回调**，执法与持续对抗交给同目录的 `jfglzsn.exe` / `przs.exe` / `zmserv.exe`。

| 项 | 值 |
| --- | --- |
| 程序集 / 输出 | `set` → `set.exe`（`OutputType = WinExe`） |
| 语言 / 框架 | VB.NET WinForms，.NET Framework 4.5，`RootNamespace = set` |
| 入口 | `StartupObject = set.Internal.InfoAttr`（`WindowsFormsApplicationBase` 子类，`IsSingleInstance = false`） |
| 权限要求 | `app.manifest` 声明 `requestedExecutionLevel level="requireAdministrator"` —— 双击即 UAC 提权 |
| 反分析 | `[assembly: SuppressIldasm]`（作者主动加，非模板默认） |
| 壳痕迹 | .NET Reactor（自实现 MD5 + AES 解密内嵌资源 `c4a6c669-082b-46ec-be30-7d414450bf0b`）+ IntelliLock 未注册水印 `This assembly is protected by an unregistered version of "IntelliLock"!` |

工程共 17 个 `.cs`，真正写业务逻辑的只有 4 个，其余是 VB 模板与壳残留：

| 文件 | 真实职责 |
| --- | --- |
| `Internal\InfoAttr.cs` | `Main`：交给 VB 应用框架，指定首个窗体 `load` |
| `WindowsApplication1\load.Designer.cs` | 密码闸门 + 「账号进程名」生成器 |
| `WindowsApplication1\Form1.Designer.cs` | **设置主窗体 + 全部载荷**（业务逻辑集中在前 2040 行） |
| `WindowsApplication1\Form3.Designer.cs` | 完成提示 + 自启动是否写成功的自检 |
| `Internal\ObserverAttr.cs` | 注册表读写中枢（`RateInfo`/`SortInfo`）+ 密码摘要 `SHA256(原文+"bfdshgs")` |
| `Internal\CandidateAttr.cs`、`AttrAttr.cs`、`My\*` | `My.Computer` / `My.Forms` / `My.Settings` 模板 |
| `Internal\CandidateCandidate.cs`、`CollectionAttr.cs` | Reactor 运行期：内嵌程序集按需解密加载、自实现 MD5（本工程内无调用点） |
| `Internal\TokenAttr.cs`、`ILLicenseModule.cs`、`AdapterAttr.cs`、`ProducerCandidate.cs`、`-Module-{GUID}.cs` | 壳水印 / 资源模板 / 死代码桩 |

## 二、界面与交互流程

### 2.1 启动链

`InfoAttr.主入口`（`[STAThread]`）→ `Application.SetCompatibleTextRenderingDefault` → `CandidateAttr.应用程序.Run(args)` → `OnCreateMainForm` 把主窗体设为 `load`。
**注意启动窗体不是 `Form1`**：密码验证窗口在前，设置界面在后。

### 2.2 `load`：密码闸门（534×262，居中，标题 `load`）

- 界面：「输入小助手密码：」+ 密码框（`PasswordChar = '*'`）+「确 定」按钮 + 一个红字提示 Label。
- `Form_Shown`：读 `HKCU\Software\n`；**为空（从没设过密码）就直接隐藏自己并 `Form1.Show()`** —— 不做任何授权判断，「密码」是管理员自己设的门锁，不是授权码。
- 点「确 定」：长度 < 6 → 提示「密码应该是6位以上的字母或数字，请重新输入！」；否则算 `SHA256(Trim(输入) + "bfdshgs")`，与小写十六进制串 `HKCU\Software\n` 逐字符比较，相同则隐藏本窗体、打开 `Form1`；不同则提示「密码不正确，请重新输入！」。
- `Form_Load` 顺手按「月 × 日」生成 5 字符随机名（`Chr(105 + 数字)`，落在 `i`~`r`）写入静态字段 `ObserverAttr.账号进程名`（`访客名` 多带 `.exe`）。这个随机名后面被 `Form1.CallInfo` 当「要杀掉的账号进程」用。
- 大号空白标签的双击事件是**空方法**，没有彩蛋。

### 2.4 打开时回填（`Form1_Load` / `AwakeInfo`）

逐项读 `HKCU\Software\jfglzs` 的 `dzjs`、`usb_jianche`、`shadu_jianche`、`cmd_jianche`、`win_jian`、`games_jianche`、`bianhao`、`xiazai`、`gaowei`、`zcb`，按 `"off"`/`"on"` 还原单选状态。学生端路径为空时依次探测 `studentMain`（极域）、`ClassMangerApp`（锐捷云课堂）、`REDAgent`（红蜘蛛）三个进程的 `MainModule.FileName`。

**首次运行（注册表全空）时几乎全部落到「禁止」分支**：`usb_jianche`/`shadu_jianche`/`cmd_jianche`/`games_jianche`/`xiazai` 判等 `"off"` 失败、`win_jian` 判等 `"on"` 失败，于是勾中「禁止」；`gaowei` 与 `zcb` 取默认值 2，勾中「仅 C++ 可生成新 exe」和「自动关闭」。——即**默认姿态就是最严的那一档**。

### 2.6 关闭行为

`Form1.FormClosing` 与 `Form3` 的「确 定」都调用 `ProjectData.EndApp()`——相当于 VB 的 `End`，**不触发窗体正常收尾，直接掐断进程**。

## 三、核心行为

### 3.1 策略下发（`DefineInfo`，32 个动作块）

这是本组件危害最大的一段，全部经 `ObserverAttr.RateInfo` 写入（子键不存在会自动创建；写入异常被包成 `Exception` 抛出，由调用方的 try/catch 吞掉，所以某一条失败不影响后面的块）。

### 3.2 服务安装与自启动（持久化）

| 动作 | 命令原文 |
| --- | --- |
| 删旧服务 | `sc delete zmserv` |
| 建服务 | `sc create zmserv binPath= <程序目录>\zmserv.exe start= auto` |
| 设失败动作 | `sc failure zmserv actions= "reboot/60000/reboot/60000/reboot/60000" reset= 300` |
| 停服务（清场） | `net stop zmserv` |

`sc failure` 的含义是**服务三次失败后每隔 60 秒重启整台机器**——看门狗被掐死就等于机器被反复重启，这是家族最狠的一条反清除手段。配合 3.1 的 `prozs` / `jfglzsn` 两条 Run 键（各写两遍），构成「服务 + 双 Run 键」的持久化组合。

### 3.3 文件系统操作

- **U 盘/电子教室相关**：把学生端 exe 复制成 `<学生端路径>2`（备份），并把同目录的 `SpecialSet.exe` 设为 `Hidden|System`。目录算法是 `Mid(副本路径, 1, Len-16)`——**写死假设文件名长 15 字符**，换个名字的客户端会算错路径（原版缺陷）。
- **数据目录**：建 `c:\windows\jf`，把 `jfglzsn.exe`/`przs.exe`/`zmserv.exe` 复制进去并改名成 `jfglzsn.dat`/`przs.dat`/`zmserv.dat`，目录与三个文件全设 `Hidden|System`。这是家族的「隐藏备份」，被杀后能从这里还原。
- **隐藏的同伴文件**：`jfglzsn.exe`、`zmserv.exe`、`przs.exe`、`set.exe`、`uninstall.exe`、`about.exe`、`yl.wav`、`huifu.wav`、`hmd_local.txt`、`regini.exe` 逐个加 `Hidden|System`。
- **收尾删除**：`yl.reg`、`huifu.reg`（临时导出的注册表脚本）。
- **永久删除**：`CollectInfo` 结束时把 `zy\` 目录树（含子目录）下的所有文件 `DeleteFile(..., RecycleOption.DeletePermanently, ...)` —— 马甲 exe 派发完就地销毁，回收站里也找不到。

| `双核浏览器` | `zy\双核浏览器.exe` | `HKCU\Software\shuanghe` |
| `Firefox` / `firefox` | `zy\Firefox.exe` | `HKCU\Software\firefox` |
| `Microsoft Edge` | `zy\Microsoft Edge.exe` | `HKCU\Software\edge`（仅当快捷方式目标含 `.exe`） |
| `谷歌浏览器`（假 Chrome） | **不替换，直接删** | — 并弹「删除桌面上假google chrome的快捷方式…」 |

细节：

- 处理 `.lnk` 时先用 `WScript.Shell.CreateShortcut(...).TargetPath` 读出真实目标（`ReadShortCut`，用完 `ReleaseComObject`），把路径记进上表右侧的注册表值，**再** `Kill` 快捷方式、放马甲 exe——先记真身再换门面，便于必要时还原。
- 一个浏览器都没找到时，往桌面塞 `zy\百度搜索&网址导航.url`。
- 最后删掉桌面上名字含「网址导航 / 上网导航 / 百度一下」的 `.lnk`，清掉竞品入口。
- 整个方法体在 `checked { }` 上下文中（VB 默认语义）。

### 3.5 快捷方式与收藏夹劫持（`UpdateInfo`）

| 目标 | 操作 |
| --- | --- |
| `%APPDATA%\Microsoft\Internet Explorer\Quick Launch` | `FileSystem.Kill("<目录>\*.*")` 清空，再放入 `zy\Internet   Explore.lnk`（三空格 + `Explore` 拼写都是作者原文） |
| `...\Quick Launch\User Pinned\TaskBar` | 同上：清空任务栏固定项，塞同一个 lnk |
| 收藏夹 `links` 目录（路径从 `HKCU\...\Explorer\Shell Folders` 的 `Favorites` 读） | 连做两遍 `Kill` + 两遍 `File.Copy`，放入 `zy\百度搜索&网址导航.url` |
| `HKCU\Software\Microsoft\Internet Explorer\LinksBar` → `Enabled` | `1`（强制打开 IE 链接栏） |

代价是**用户原有的快速启动、任务栏固定项、收藏链接被整目录清空**。

### 3.6 hosts 劫持（`DeleteInfo` / `FlushInfo`）

1. 先用 `IsPortOpen("www.baidu.com", 443, 2000)` 判网络，不通就置 `hosts已改动 = false` 退出。
2. 用 `WebClient.DownloadFile(名单地址, "c:\1.txt")` 下载名单——**固定落到 `c:\1.txt`**（本地名单 `hmd_local.txt` 走同一条路径，靠 `WebClient` 接受本地路径）。
3. 首行必须含 `www.` 才继续（作者自己的「有效名单」校验）。
4. 逐行扫两个分组标记：`视频网站：`（记下 `视频块起始 = 行号-1`、`视频块结束 = 行号+1`）与 `产品名：`（记 `产品名行 = 行号-1`）。
5. 把 `C:\Windows\System32\drivers\etc\hosts` 属性改回 `Normal`（连写两遍），读全文，收集已有 `127.0.0.1 <域名>` 行做成去重集合。
6. 追加主名单（`视频网站：` 之前的行）：每行去掉 `http://` / `https://`、按 `/` 截断、转小写，写成 `127.0.0.1 <域名>`，已存在则跳过。
7. 模式为 `"off"` 时再追加 `视频网站：`~`产品名：` 之间那段。**但本组件三个调用点传的模式恒为 `"on"`，所以视频段实际永远不会被追加**——这段分支在本组件内是死路。
8. 写回 hosts → `hosts已改动 = true` → hosts 设 `ReadOnly|Hidden|System` → `DisableCMD=0` → `ipconfig /flushdns`。

`FlushInfo(域名)` 是单条版本：hosts 里没有 `127.0.0.1 <域名>` 就整份重写追加一条（本工程内无调用点）。

### 3.7 清场、杀进程与锁鼠标（`CallInfo`）

1. 反复杀 `ObserverAttr.账号进程名`（`load` 生成的 `i`~`r` 5 字符随机名）与 `jfglzsn`，直到两者都查不到——`do/while` 条件读 `[0]` 会抛越界，原版靠 `On Error Resume Next` 吞掉，这里用逐条 try/catch 复现，循环仍能退出。
2. 遍历**所有**进程，把「名字长度 ≥ 4 且每个字符 ASCII 都落在 102~111（`f`~`o`）」的进程全部 `Kill()`。`102` 来自代码里的 `字符下界 = 10; 字符下界 = 字符下界 * 10 + 2`——这个特征区间正好套住上一条那批随机名。
3. `DisableCMD=0` → `net stop zmserv` → `Sleep(1000)` → 再补杀一次 `zmserv` 进程。
4. `ClipCursor` 把鼠标指针限制在主屏矩形（0,0,屏宽,屏高）内。

### 3.8 壁纸（`VisitInfo` / `ForgotInfo` / `ResetInfo`）

校验文件存在 → 写 `HKCU\Control Panel\Desktop` 的 `Wallpaper`（图片路径）与 `WallpaperStyle`（固定 `"2"`）→ `SystemParametersInfo(20, 0, 路径, 3)`（`SPI_SETDESKWALLPAPER`）立即生效。传入的 `WallpaperStyle` 枚举参数**从未被使用**（`Tiled=1`/`Centered`/`Stretched=6` 三个值都是装饰）；「恢复默认桌面」写死 `C:\Windows\Web\Wallpaper\Windows\img0.jpg`。两处异常文案都是原版 bug 里的 `"设置失败: {ex.Message}"`（没有插值符）。

### 3.9 探测与工具函数

| 函数 | 行为 |
| --- | --- |
| `IsPortOpen(host, port, timeout=2000)` | `TcpClient.BeginConnect` + `WaitOne(timeout)`，连上返回 true（实际被大量使用） |
| `CheckInfo(进程名)` | `GetProcessesByName(名).Length > 0` |
| `GetProcessPathsByName(名)` | 取同名进程 `MainModule.FileName`（同名多个时只留最后一个；异常返回 `null`） |
| `RegisterInfo(主机, 超时)` | `Ping.Send` 判 `IPStatus.Success`——**本工程内无调用点**（死代码） |

## 四、与其他组件的关系

`set.exe` 是「装填器」：它把配置、服务、自启动、马甲文件一次性铺好；持续执法的那几个组件（`jfglzsn.exe` 定时器与 WMI 回调、`przs.exe` 驻留锁屏、`zmserv.exe` 看门狗服务，据仓库 README 的组件清单）都不是本工程的东西。本组件与它们**没有代码级引用**，只通过注册表值、文件路径和进程名松耦合。

| 对象 | 本组件的动作 | 代码依据 |
| --- | --- | --- |
| `zmserv.exe` / `zmserv` 服务 | `sc delete` → `sc create ... start= auto` → `sc failure ... reboot/60000`；清场时 `net stop` 并杀进程；文件另存 `c:\windows\jf\zmserv.dat` | `DefineInfo` 第 13/19/30 步、`CallInfo` |
| `przs.exe` | 写 `HKLM\...\RUN\prozs` → `<程序目录>\przs.exe`（两遍）；另存 `przs.dat` | `DefineInfo` 第 15/30 步 |
| `jfglzsn.exe` | 写 `HKLM\...\RUN\jfglzsn`；`CallInfo` 里反复 `Kill` 进程名为 `jfglzsn` 的进程（先杀自家守护进程，随后由本组件重建服务与 Run 键）；另存 `jfglzsn.dat` | `DefineInfo`、`CallInfo` |
| `about.exe` / `uninstall.exe` | 只被设成 `Hidden + System`，本组件既不启动也不校验 | `DefineInfo` 第 31 步 |
| `zy\` 下 11 个马甲浏览器 exe | 复制到桌面/公共桌面顶替真实浏览器，随后整目录永久删除 | `CollectInfo` |
| 电子教室学生端（`studentMain` / `ClassMangerApp` / `REDAgent`） | 探测其 exe 路径；把 exe 复制成 `<路径>2` 备份；隐藏同目录 `SpecialSet.exe` | `AwakeInfo`、`ConcatInfo`、`DefineInfo` 第 11 步 |
| `HKCU\Software\n`（密码摘要） | 本组件**写**（`DefineInfo` 第 19 步），`load` 与 `Form3` 自检时**读** | `ObserverAttr.InstantiateInfo` |
| `HKCU\Software\jfglzs\*` | 本组件**写**全部 10 项配置与 `zhuye`；本组件自身没有定时器，只在下一次打开时读回显示 | `AwakeInfo` / `DefineInfo` |
| 随机「账号进程名」 | `load` 生成 → `ObserverAttr.账号进程名` → `CallInfo` 当猎杀目标 | `load.LogoutInfo`、`CallInfo` |

两处可以确定的**协作契约**：

1. **密码同源**：`SHA256(明文 + "bfdshgs")` 的十六进制小写串存在 `HKCU\Software\n`，本组件的闸门校验、`Form3` 的权限自检都围绕它；家族里凡是要「用同一把密码放行/退出」的组件，都读这个值。
2. **配置同源**：`set.exe` 只负责把开关写进 `HKCU\Software\jfglzs`，谁去执行（禁 U 盘、杀游戏、拦下载）由常驻组件按这些值决定——这一点由本组件「写完就不管、无任何监控逻辑」反推得出。

另外，注册表里删掉 13 个 `Image File Execution Options\<游戏>.exe` 子键这一动作，反证了**家族在别处用 IFEO 劫持屏蔽系统游戏**：管理员选「小游戏允许」时，`set.exe` 负责把这些劫持清掉。

## 六、危害总结

1. **一次点击即整机接管**：`requireAdministrator` 提权后，一个「保存设置」把注册表策略、服务、自启动、hosts、文件属性、浏览器入口全部改写，用户几乎没有逐项确认的机会。
2. **顽固持久化 + 反清除**：服务自启 + `HKLM` 双 Run 键（各写两遍）+ `sc failure` 三连 `reboot/60000`。杀看门狗 = 触发重启，这是比单纯自启更恶劣的一层。
3. **系统功能被成片阉割**：U 盘、命令提示符、注册表编辑器、Win 键、任务栏右键、文件夹选项、隐藏文件显示、应用商店、任务栏搜索、浏览器下载/另存、IPv6，外加**关闭 Windows 防火墙**——被管控的机器同时被削掉了自我防护。
4. **恢复通道被拆**：删 `SafeBoot\Network`（断带网络的安全模式）、`bcdedit` 关启动菜单并删指定 GUID 引导项、`checkedValue=0` 让「显示隐藏文件」永久失效、hosts 与 `etc` 目录设只读+隐藏+系统。普通用户基本失去自救路径。
5. **用户数据与浏览器被替换**：清空快速启动/任务栏固定项/收藏夹 `links`，用自带马甲 exe 覆盖桌面与公共桌面的 11 类浏览器入口，最后把 `zy\` 永久删除——证据连同原件一起消失。真实安装路径被记进 `HKCU\Software\<品牌>`，先记后换，是可还原也是可利用的痕迹。
6. **网络层劫持**：从 `http://<zhuye>/hmd_net.txt` 拉名单写 `127.0.0.1` 黑洞，随后 `ipconfig /flushdns`；域名来源可从注册表 `zhuye` 改，具备服务端遥控改名单的能力。
7. **反取证与反分析**：`.reg` 脚本伪装成 `.wav`、主程序藏进 `c:\windows\jf\*.dat`、关键目录/文件全部 `Hidden|System`、`[assembly: SuppressIldasm]`、Reactor + IntelliLock 双层壳。
8. **访问控制形同虚设**：密码是管理员自设的门锁，首次运行不拦人；摘要为单轮 `SHA256(密码+"bfdshgs")`，固定盐、可离线爆破；且 `DefineInfo` 把摘要明文写进当前用户注册表，任何能读 `HKCU\Software\n` 的进程都能拿到。
9. **明确的「以管理员身份重跑」引导**：`Form3` 在检测不到自启动项时，直接教用户右键 `set.exe` 以管理员身份再执行一次——把提权失败当成待修复的用户操作，而不是拒绝。
