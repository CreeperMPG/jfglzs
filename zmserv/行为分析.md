# zmserv 行为分析

> 所属家族：机房管理助手（jfglzs13）· 组件定位：**防卸载看门狗服务（强制关机保险）**
> 分析基于反混淆还原后的代码（`decompiled/zmserv/`），非恶意样本运行观察。

## 一、程序概览

`zmserv` 是一个 **Windows 服务**（`ServiceBase`，服务名 `Service1`，安装目录 `C:\windows\jf`），没有图形界面，全后台运行。它的唯一使命：**监控家族主程序 jfglzsn 是否存活，一旦发现主程序被杀，就强制关机报复用户**。这是整个家族"反卸载"的最后保险。内部类混淆为 `*Reg` 系列（ClassReg/ComparatorReg/CustomerReg/DicReg/DispatcherReg/ListReg/RegReg/ValueReg）。

## 二、无界面（服务进程）

- 入口：`ProcessMonitorService.Main` → `ServiceBase.Run`
- 由 jfglzsn/set 通过 `sc create zmserv binPath= C:\windows\jf\... start= auto` 安装
- 服务名伪装为通用名 `Service1`，路径藏在 `C:\windows\jf\`

## 三、核心行为（看门狗逻辑全链）

### 1. 启动时生成随机进程名（OnStart）
- 用**当天日期**（月×日）做种子，经取模运算生成 4~5 字符随机名（如 `abec`）
- 该名字 + `.exe` 就是"影子进程名"（`shadowProcessName`/`policyExeName`）
- 与 jfglzsn 每日生成的随机名**同源同种子**，保证两边一致

### 2. 30 秒扫描（PrintList）
- 每 30 秒检查进程列表里有没有 `jfglzsn`
- **一旦发现 jfglzsn 在运行** → 切换为 5 秒紧轮询模式（watchdogTimer）

### 3. 5 秒紧轮询 + 强制关机（TestList）
- 每 5 秒检查：`jfglzsn` 与影子进程**是否同时消失**
- 若同时消失（说明被杀了）→ 计数器 +1
- **计数器 ≥ 16 次（约 80 秒）→ 触发强制关机**：
  - `RtlAdjustPrivilege(19, ...)` 自提权（SeShutdownPrivilege）
  - `NtShutdownSystem(2)` 底层关机（绕过普通权限检查）
  - 兜底 `Process.Start("shutdown", "/s /f /t 0")`
- 若进程恢复运行 → 计数器清零

### 4. 强制重启（ForceRestart）
- `NtShutdownSystem(1)` 强制重启，逻辑与关机相同

### 5. 自我保护
- `OnStop` 只停定时器；服务本身被 `sc delete` 时由 jfglzsn 检测后**重新创建**（家族自愈链）

## 四、与其他组件的关系

```
jfglzsn ──sc create──▶ zmserv（本服务）
   ▲                      │
   │ 被杀                 │ 30s/5s 轮询
   └──强制关机报复◀────────┘
```

- **被 jfglzsn 创建**：jfglzsn 的 Timer_main 启动序列负责安装
- **监控 jfglzsn**：核心逻辑围绕 jfglzsn 进程存在性
- **与卸载器时序**：uninstall/about 的卸载流程必须**先 `net stop zmserv` 再杀 jfglzsn**，否则触发关机（Form4 甚至专门临时放开 DisableCMD 来执行 `net stop zmserv`）

## 五、持久化与配置

| 项 | 值 |
|----|----|
| 服务名 | `Service1`（伪装） |
| 安装路径 | `C:\windows\jf\`（binPath） |
| 启动类型 | auto（自启） |
| 随机进程名 | 日期种子（月×日），4~5 字符 + .exe |
| 关机阈值 | 连续 16 次检测（≈80 秒）双进程同时消失 |

## 六、危害总结

- **最恶劣的报复机制**：用户/管理员一旦杀主程序，**整个电脑被强制断电关机**（NtShutdownSystem 绕过软件层拦截）
- **数据丢失风险**：80 秒倒计时后无警告直接关机，未保存工作全部丢失
- **绕过常规防御**：RtlAdjustPrivilege + NtShutdownSystem 属于内核级关机路径，普通杀软难以拦截
- **与主程序互为保险**：jfglzsn 被杀 → 关机；zmserv 被删 → jfglzsn 重建。必须**同时、按顺序**清除

> 结论：zmserv 是家族"防卸载"的核心威慑，也是最危险的组件；应急处置时，**第一优先级是先停掉它**（net stop zmserv），再处理其他组件。
