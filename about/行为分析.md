# about 行为分析

> 所属家族：机房管理助手（jfglzs13.4）· 组件定位：**信息/关于 + 退出解锁组件**
> 分析基于反混淆还原后的代码，非恶意样本运行观察。

## 一、程序概览

`about.exe` 是这套管控软件里唯一带**图形控制面板**的组件，程序集名 `about`、根命名空间 `WindowsApplication1`，VB.NET + WinForms，目标框架 .NET Framework v4.5，输出类型 `WinExe`。

- **启动对象**：`WindowsApplication1.Internal.ComposerMapper`。`[STAThread] 程序入口` 先调 `Application.SetCompatibleTextRenderingDefault`，再走 `My.Application.Run(args)`；`OnCreateMainForm` 把主窗体设为 `My.Forms.Form1`。
- **运行参数**：`IsSingleInstance = false`（不做单实例互斥，可同时多开）、`EnableVisualStyles = true`、`SaveMySettingsOnExit = true`、`ShutdownStyle = AfterMainFormCloses`（主窗体关闭即进程结束）。
- **权限**：`app.manifest` 声明 `requestedExecutionLevel level="requireAdministrator"`——面板一启动就要求管理员，这是它能改 `HKLM` 策略键、停服务、杀任意进程的前提。
- **程序集身份被壳抹平**：版本 `1.0.0.0`、公司/产品/版权/商标全为空串、GUID `ca03f0bd-3033-4420-8b48-e574750c6d44`、无强名称签名、带 `SuppressIldasm`（阻止 ILDasm 反汇编）。
- **代码成分**（同一程序集里混了四类）：
  1. 业务：`Form1`（面板）、`Form3`（退出密码窗）、`Internal/SetterMapper`（注册表 + 密码哈希）；
  2. .NET Reactor 运行时：`InstanceMapper`（字符串池解密 / 自改内存）、`IssuerMapper`（内嵌程序集解析）、`DescriptorMapper`（混淆控制特性）；
  3. IntelliLock 残留：`ILLicenseModule`、`Internal/ListenerMapper`（未注册提示，无调用点）；
  4. VB `My` 模板：`ComposerMapper`、`ExpressionMapper`、`MySettings*`、`MapperMapper`、`ErrorMapper`。

一句话定位：它不常驻、不联网、不落文件，但它同时是**监控端的开关面板**和**整套管控的解除闸门**——一条密码通过，USB、浏览器下载、开发者工具、命令提示符、监控进程与服务全部被放开。

它的名字虽然被登记为「关于」，但工程里**没有 AboutBox**：所谓"关于信息"只是主窗体上的三段文字（版本标题、官网链接、帮助链接），其余全是操作入口。

### 主窗体 Form1

标题固定 `学生机房管理助手v13.4`，`ClientSize 682×486`，`CenterScreen`，`AutoScaleDimensions 6×12`，背景图与图标来自 `Form1.resources`。没有 `FormClosing` 拦截、没有改 `ControlBox`，因此**右上角 × 可以直接关掉面板**（只结束本进程，不解除任何管控）。

### 「退出程序」窗体 Form3

标题 `退出程序`，`ClientSize 417×181`。密码框 `PasswordChar = '*'`，标题 `输入小助手密码：`，按钮 `退出(需10秒)`，红色提示标签初始为空，底部固定说明：`注：用密码退出后可使用U盘、下载文件，停止监控。`

窗体通过 `ExpressionMapper.VisitComposer.Form3.Show()` 以**非模态**方式打开，且实例由 `My.Forms` 的窗体缓存持有（关闭后再次打开仍是同一实例，缓存命中时不重建）。没有设置 Owner，也没有阻止重复点击——按钮禁用只发生在进入退出流程之后。

### 交互流程（按代码顺序）

1. 进程启动 → `ComposerMapper` → `My.Forms.Form1`（首次访问时构造）→ 构造函数先挂 `Load` 处理器、再初始化控件 → 显示窗体 → `Load` 触发**进程名生成** → Timer 开始 500ms 轮询。
2. 状态轮询只看 `jfglzsn` 一个进程名：不在 → `关 闭`；在 → `正在运行中。。。`。它**不检查**按日期算出的那个随机名进程，所以监控端以随机名启动时面板可能显示不一致。
3. `设  置` → 打开配置程序（`set.exe 1`）。
4. `启动程序` → 读 `HKCU\Software\n` 判分支：空（从没设过密码）→ 只拉 `set.exe`；非空（设过密码）→ 拉 `przs.exe` 与 `jfglzsn.exe`。随后杀掉全部 `explorer` 并重启。
5. `退出程序` → 同样是先读 `HKCU\Software\n`：空 → 打开 `set.exe`（**并不是退出**）；非空 → 弹 Form3 要密码。
6. Form3 点击 `退出(需10秒)` → 长度检查 → 哈希比对 → 通过后依次"停监控 → 放开浏览器策略 → 放开 USB 策略 → 重启桌面"→ 成功后 `Close()` 自己。

## 三、核心行为

### 1. 启动即生成一个"每天变化"的监控进程名

`窗体加载_生成助手进程名` 在 `checked` 上下文里跑两步，两段都写 `SetterMapper.小助手进程名` / `小助手可执行文件名`（后一步覆盖前一步，原版残留逻辑，但两次赋值都是真实副作用）：

- **第一步**：`月日乘积 = 当月 × 当日` → 取 `%7 / %9 / %5 / %3` 四个余数 → 用 `Strings.Chr(97/98/101/99 + 余数)` 拼 4 个小写字母名，`月日乘积 % 2` 的奇偶决定两套字母排列。
- **第二步**（真正生效）：`VBMath.Randomize(月日乘积)` 播种 → `Rnd()` → `Math.Round(Rnd() * 100000 * 3 + 1)` → 循环 5 次 `Chr(数字 % 10 + 105)`，得到 5 个落在 `i`..`r`（ASCII 105–114）之间的字符。

结果：监控端的进程名**每天由"月×日"唯一确定**，同一台机器同一天固定不变，换机器也一样。这不是随机，而是按日期生成的固定序列——目的是让"监控进程名"无法用一条 kill 规则长期命中，同时作者自己（以及 Form3）能算出来去精确结束它。可执行文件名同步写成同名 + `.exe`。

### 2. 状态监视

`Timer1` 每 500ms 调 `Process.GetProcessesByName("jfglzsn")`，`Length > 0` 即视为"正在运行"。只读不写，不做任何恢复动作。

### 3. 「启动程序」：拉起同目录伴生程序并重启桌面

- 分支依据：`HKCU\Software` 值 `n` 是否为空串（`Operators.CompareString` 精确比较，区分大小写参数为 false）。
- 无密码：`Process.Start(<程序目录>\set.exe)`；有密码：`Process.Start(<程序目录>\przs.exe)` 与 `Process.Start(<程序目录>\jfglzsn.exe)`。
- 随后枚举 `explorer` 进程逐个 `Kill()`，再 `Process.Start("explorer.exe")`。
- 原版整段是 `On Error Resume Next`，反混淆后**每条可能抛异常的语句各自 try/catch**：某一步失败（例如文件缺失）不会中断后续步骤，这是刻意保留的语义。
- 同文件里还有 `启动更新器_未绑定` → `Process.Start(<程序目录>\更新器.exe)`，**没有绑定任何控件或事件**，是死代码；但它说明发行包内还有一个独立更新器。

### 4. 「退出程序」：唯一的密码闸门，通过后解除全部管控

密码校验（`退出按钮_Click`）：

1. `Strings.Len(输入) < 6` → 提示 `密码应该是6位以上的字母或数字，请重新输入！`、清空输入框、结束；
2. `SHA256(UTF8(Trim(输入) + "bfdshgs"))` 转 64 位小写十六进制；
3. 与 `HKCU\Software` 值 `n` 做字符串比较；
4. 不等 → 提示 `密码不正确，请重新输入！`、清空、结束；
5. 相等 → 禁用按钮、清提示，进入解除流程。

解除流程共五组动作，全部逐条吞异常（`HKLM` 写入失败也继续往下走）：

**a. `执行退出流程`（停监控）**

- 取 `服务名 = "zmserv"`、`助手进程名 = SetterMapper.小助手进程名`（第 1 节算出的随机名）、`监控进程名 = "jfglzsn"`；
- **do-while 重试**：枚举助手名进程 → `列表[0].Kill()`；枚举 `jfglzsn` → `列表[0].Kill()`；两个列表都为空时退出循环（列表为空导致的下标越界被单独吞掉，因此循环能继续）；
- **按名字形状的模糊查杀**：`字符下界 = 10; 字符下界 = 10 * 10 + 2;` 得 102（`'f'`），遍历 `Process.GetProcesses()`，凡进程名长度 ≥ 4 且**每个字符**的 ASCII 都落在 `102..111`（`'f'`..`'o'`）的，直接 `Kill()`；
- `HKCU\Software\Policies\Microsoft\Windows\System\DisableCMD = 0`（解除命令提示符禁用）；
- `Interaction.Shell("net stop zmserv", AppWinStyle.Hide, true, -1)`（隐藏窗口、同步等待）；
- `Thread.Sleep(3000)` → 杀 `zmserv` 进程 → 再来一轮 do-while 重试 → 再 `net stop zmserv` → `Thread.Sleep(2000)`；
- 终判：`jfglzsn` 与随机名进程都不在 → 弹 `退出程序成功！` 并 `Close()`；否则弹 `退出程序不成功！请重新执行退出程序命令或重启电脑` 并恢复按钮。

这里的模糊查杀与第 1 节的命名区间**只部分重叠**：生成区间是 `i`..`r`（105–114），查杀区间是 `f`..`o`（102–111），`p/q/r` 落在外面——说明这条启发式是"大致能扫到"，真正精确结束靠的是随机名 + `jfglzsn` 两个精确名。副作用是任何 4 字符以上、全部由 `f`–`o` 组成的进程名都会被误杀（例如 `mono`，ASCII 109/110/111/111）。

**b. `恢复浏览器下载策略`（12 条 DWord 策略改回"允许"）**

见第五节表格。写完后依次 `Kill()` `chrome`、`msedge`、`firefox`、`iexplorer`——注意最后一个常量**原文拼写少一个 `e`**（正确应为 `iexplore`），所以对 IE 实际无效，属作者笔误，代码原样保留。本方法自身没有 try/catch，异常由调用方吞掉。

**c. 放开 USB 存储**

写 4 处 `usbstor` 的 `Start = 3`（3 = 允许 USB 存储驱动加载）：

- `SYSTEM\CurrentControlSet\Services\usbstor`
- `SYSTEM\ControlSet001\Services\usbstor`
- `SYSTEM\ControlSet002\Services\usbstor`
- `SYSTEM\ControlSet003\Services\usbstor`

四处的根键都是 `HKEY_LOCAL_MACHINE`，每条单独 try/catch。

**d. 重启桌面**

杀全部 `explorer` → `Process.Start("explorer.exe")`，让策略立即生效。用户感知为桌面闪断、任务栏消失又回来。

**e. 关闭自己**

只关 Form3 这一个窗体，`about.exe` 主面板仍留在屏幕上（主窗体未关闭，`ShutdownStyle` 不触发退出）。

### 5. 密码工具与注册表工具（`Internal/SetterMapper`）

- `计算密码哈希`：`SHA256(UTF8(密码 + "bfdshgs"))` → 每字节 `ToString("x2")` 拼成 64 字符小写 hex。**盐 `bfdshgs` 硬编码在代码里**，等价于"公开盐单轮哈希"，密码可离线爆破，也可直接用字典命中。
- `读取注册表值`：整段 try/catch，任何异常返回 `null`；调用方用 `Conversions.ToString` 转字符串，所以"读不到"和"值不存在"都表现为空串 → 判定为"没设过密码"。
- `写入注册表值`：键不存在先 `CreateSubKey` 再写，存在则直接写（原 `goto` 已还原为 if/else）；失败抛 `写入注册表值时发生错误: ` + 原始消息。
- `删除注册表值` / `删除注册表键` / `注册表键是否存在` / `确保注册表键存在`：本工程内**没有调用点**，属给其它组件预留的能力。
- 文件顶部有 6 个 `advapi32.dll` 的 CryptoAPI P/Invoke（`CryptAcquireContext`、`CryptCreateHash`、`CryptHashData`、`CryptGetHashParam`、`CryptDestroyHash`、`CryptReleaseContext`）与 4 个常量（`1`/`-268435456`/`32771`/`2`），**全部无调用点**——真正算哈希走的是托管 `SHA256`，这批是死代码。

### 6. 壳的运行时行为（静态可见，解壳后已失效）

`Internal/InstanceMapper` 是 .NET Reactor 的运行时支撑，包含三件真实实现（其余二十来个方法恒返回 `null`/`true`/`false`，是垃圾方法）：

- **字符串池解密**：打开内嵌资源 `dac028a9-ca53-4586-8b57-452994e78968`，用硬编码 32 字节 AES key + 16 字节 IV 做 CBC 解密，再做 32 位混洗（常量 `1394801171`、`3457341307`、`4040842541`、`2018246656`），随后每条字符串用 `OpenProcess(0x10, ...)` + `ReadProcessMemory` 从自身模块内存按偏移取密文，AES 解密后缓存。目的是让静态扫描看不到明文字符串。
- **自改内存**：读内嵌资源 `c7c9a35c-0300-44ea-976c-1797ff0710b0`，用 `OpenProcess(0x38, ...)` 打开自己 → `VirtualProtect(..., PAGE_READWRITE, ...)` → `WriteProcessMemory` / `Marshal.WriteInt32` 按 RVA 回写 int32 → 恢复保护 → `CloseHandle`。这是壳的代码还原/抗篡改手法。
- **FIPS 分流与自实现 MD5**：反射读 `System.Security.Cryptography.CryptoConfig` 的 `get_AllowOnlyFipsAlgorithms`，为真时改用自己手写的 64 轮 MD5（含 64 项常量表）。

`Internal/IssuerMapper` 是内嵌依赖加载器：注册 `AppDomain.AssemblyResolve`，按 `"b0494a1f-4bd3-" + Base64(MD5(Unicode(程序集简单名)))` 拼资源名取内嵌 DLL，先 `Assembly.Load(byte[])`；抛 `FileLoadException` / `BadImageFormatException` 时回退为写文件——落 `%TEMP%\b0494a1f-4bd3-<base64>\<简单名>.dll` 再 `Assembly.LoadFile`。同时设 `RSACryptoServiceProvider.UseMachineKeyStore = true`。

**本工程现状**：解壳流程已把那两个 GUID 资源剥离（现存资源只有 `Form1.resources` 与空的 `Resources.resx`），所以这两条路径在仓库代码里是死代码；但它们记录了**原样本运行时**的真实行为，也是可用的主机侧 IOC。

### 7. 授权残留

- `ILLicenseModule`：只有 `返回真占位()` / `返回假占位()` 两个常量方法，无任何校验逻辑，无调用点。
- `ListenerMapper.显示IntelliLock未注册提示()`：静态幂等标志 → 先置标志再 `MessageBox.Show("This assembly is protected by an unregistered version of \"IntelliLock\"!", "www.eziriz.com")`，异常时退化到一个空实现的"写入警告脚本"（脚本内容为一段 `javascript:alert(...)`）。同样无调用点。
- 两者共同说明：这套程序在换成 .NET Reactor 之前曾用 IntelliLock 加壳/授权，且这些残留对实际授权判断零影响。

### 8. 机器标识读取（未被使用）

`Form3.计算机器编号()` 取环境变量 `COMPUTERNAME` 的**最后一个字符的 ASCII**，变量为空时固定返回 `88`（字符 `X`）；变量取不到（`null`）会抛 `NullReferenceException`，原版同样如此。本程序集内没有调用点，推测给监控端区分机位用。

## 四、与其他组件的关系

about 本身不做安装、不做持久化、不做拦截，它的价值在于**串起其它组件**。

| 组件 | 关系 | 代码证据 |
| --- | --- | --- |
| `set.exe`（配置/部署） | 双向。about 的「设置」菜单与"无密码"分支都打开它（参数 `1`）；它负责把退出密码 `SHA256(密码 + "bfdshgs")` 写进 `HKCU\Software\n`，也就是 Form3 要校验的那个值；部署阶段还会把同目录 `about.exe` 设成"隐藏 + 系统"属性，让面板在资源管理器里不可见 | `Form1.设置_Click`、`Form1.退出程序_Click`、`Form1.启动小助手_Click` |
| `jfglzsn.exe`（监控端/小助手） | about 的状态轮询、精确查杀、无密码分支拉起的对象都是它；它自身负责注册并守护 `zmserv` 服务 | `Form1.定时检查小助手状态`、`Form3.执行退出流程` |
| `przs.exe`（守护/拦截） | 两条通道：① about 在"已设密码"分支启动 `przs.exe`；② przs 的托盘图标单击会启动 `<程序目录>\about.exe`——**这是用户进入面板的常规入口**（面板文件本身被隐藏，不能双击） | `Form1.启动小助手_Click`、`przs\Form1.Designer.cs` 托盘点击处理器 |
| `zmserv.exe`（系统服务） | Form3 的解除流程两次 `net stop zmserv`，中间夹一次按名杀进程，最终以"两个进程都不在"作为成功判据 | `Form3.执行退出流程` |
| `uninstall.exe` | 另一条"受密码保护的出口"，用同一套 `SHA256(输入 + "bfdshgs")` 与 `HKCU\Software\n` 校验，但动作是彻底卸载 | 见 uninstall 工程同名流程 |
| `更新器.exe` | 仅出现在 about 的死代码里，未绑定任何事件 | `Form1.启动更新器_未绑定` |
| `yz.exe` | about 不引用；由 przs 一侧按"程序所在目录"拼路径启动，与本组件无直接交互 | 见 przs 工程路径推导 |

分工可以概括为：`set.exe` 负责"装与配"，`zmserv.exe` + `jfglzsn.exe` + `przs.exe` 负责"守与拦"，**`about.exe` 负责"看与放"**，`uninstall.exe` 负责"拆"。about 是其中唯一由普通用户可直接点开、也唯一提供"输入一条密码就整体解除"的界面。

另外，三处密码判断（about 的 Form3、przs、uninstall）与 `jfglzsn` 内部的口令摘要共用同一个算法和同一个注册表值，因此**一处泄露等于处处可用**。

## 五、持久化与配置

about 自身**不建立任何自启动项、不写文件、不联网**：`Process.Start` 的目标只有同目录 exe 和三个官网 URL，唯一的文件写入在 `IssuerMapper` 的 `%TEMP%` 回退路径（解壳后已无资源可解，不会触发）。

它唯一的**读**配置是退出密码；它真正留下的改动是"把管控键改回允许值"。

### 读取项

| 项 | 值 | 含义 |
| --- | --- | --- |

## 六、危害总结

1. **一条密码即全面解除管控**。Form3 校验通过后同时做五件事：按名结束监控进程、按 ASCII 形状模糊查杀、`net stop zmserv`、把 12 条浏览器限制与 USB 存储、命令提示符限制改回允许、重启桌面让策略立即生效。这不是"退出程序"，而是"临时撤防"——窗体说明文字自己也写着「用密码退出后可使用U盘、下载文件，停止监控」。
2. **密码闸门的强度很弱**。单轮 `SHA256` 加固定公开盐 `bfdshgs`、最短 6 位、结果存在**当前用户可写**的 `HKCU\Software`。同一用户权限下的任何程序都能改写或删除该值：删掉即回到"未设密码"状态，此时「退出程序」按钮会改为直接打开配置程序 `set.exe`——闸门从"要密码"退化为"要另一个程序"。据代码注释，这个值与 `przs`、`uninstall`、`jfglzsn` 共用，一处泄露全线可用。
3. **无差别杀进程**。`执行退出流程` 里的启发式：进程名长度 ≥ 4 且每个字符的 ASCII 都在 `102..111`（`f`–`o`）就 `Kill()`。任何符合该形状的无关进程都会被误杀（如 `mono`），且循环里没有白名单、没有排除自身、没有确认提示。
4. **强制重启用户桌面**。about 的两条主要路径（「启动程序」与 Form3 解锁）都以"杀掉全部 `explorer` 再 `Process.Start("explorer.exe")`"收尾，用户当前会话的桌面、任务栏、已打开的资源管理器窗口会全部中断。
5. **系统级策略写入并持久生效**。`usbstor\Start`、Edge/Chrome/Firefox 下载与开发者工具策略都在 `HKLM`，写入后不会自动回滚——程序退出、重启都保留"允许"状态，直到 `set.exe` 或 `zmserv` 重新收紧。清单申请了 `requireAdministrator`，使它确实具备这个能力。
6. **进程名规避与"每天换名"**。监控端进程名由"月×日"派生，同一天内固定、跨天变化，使基于固定名字的查杀规则失效；about 自身被 `set.exe` 置为"隐藏 + 系统"属性，用户在资源管理器中看不到它，只能从 `przs` 托盘进入。
7. **反分析与隐蔽分发**。程序集清空了全部厂商信息、版本统一 `1.0.0.0`、无签名、带 `SuppressIldasm`；壳的运行时用内嵌资源 + 硬编码 AES key 藏字符串、用 `ReadProcessMemory` 从自身模块取密文、用 `VirtualProtect` + `WriteProcessMemory` 改自己代码段，并在必要时把内嵌 DLL 落到 `%TEMP%\b0494a1f-4bd3-<base64>\`。
8. **信息面与无害部分**。about 自身不联网、不写自启动、不落文件（除上述壳回退路径）；三个 `www.jfglzs.com` 地址只是交给默认浏览器打开。`ILLicenseModule`、`ListenerMapper`、六个 CryptoAPI P/Invoke、若干"恒真/恒假"桩全部无调用点，属壳与模板残留。
