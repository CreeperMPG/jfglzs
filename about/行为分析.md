# about 行为分析

> 所属家族：机房管理助手（jfglzs13）· 组件定位：**信息/关于 + 退出解锁组件**
> 分析基于反混淆还原后的代码（`decompiled/about/`），非恶意样本运行观察。

## 一、程序概览

`about` 是一个 VB.NET WinForms 程序，带图形界面，扮演"家族门户"角色：
- **Form1**：主窗体（关于/入口窗体），加载时生成随机监控进程名
- **Form3**：**「退出程序」密码验证窗体**——这是本组件最有价值的部分，负责整个家族的"解锁退出"流程
- **Internal/\*Product.cs**：一组被混淆重命名的内部辅助类（"产品"系列），提供注册表、响应包装等工具函数

它是**有界面的**，但界面服务于卸载/退出流程，不是普通软件的样子。

## 二、界面与交互流程

### Form1（关于窗体）
- 启动后挂接 Load 事件：**生成随机监控进程名**（与 zmserv 服务使用的影子进程名同源，每日变化）
- 控件布局由手工版 Designer 初始化（`InitializeComponent` 手写版本）

### Form3（退出密码验证窗）
用户交互流程：
1. 显示密码输入框，要求输入 **6 位以上密码**
2. 密码与注册表 `HKCU\Software\n` 中保存的 `SHA256(密码 + "bfdshgs")` 哈希比对
3. 校验通过 → 执行**整套解锁流程**；失败则拒绝退出

## 三、核心行为

### 退出解锁流程（Form3 核心，原控制流混淆已还原）
输入正确密码后依次执行：

1. **杀监控进程/服务** —— 结束家族常驻进程与 zmserv 服务
2. **恢复 USB 策略** —— 撤销"禁用 U 盘"的注册表限制
3. **恢复浏览器策略** —— 撤销假浏览器快捷方式替换与 hosts 篡改
4. **恢复 CMD 策略** —— 撤销 DisableCMD 限制
5. **重启 explorer.exe** —— 让桌面恢复正常

### 随机监控进程名生成（Form1 Load）
- 生成方式：基于日期算法（月×日为种子）生成 4~5 字符随机名，形如 `abec.exe`
- 该名字与 zmserv 的 `shadowProcessName` 呼应——**家族用随机进程名躲藏，卸载时必须知道当日名字才能清干净**

## 四、与其他组件的关系

```
jfglzsn（核心） ──安装──▶ zmserv（看门狗服务）
     ▲                         │
     │ 被杀时强制关机           │ 30秒轮询监控
     └──────────────┬──────────┘
                    │
about（退出解锁）──杀进程+杀服务+恢复策略──▶ 正常退出
```

- 与 **zmserv**：解锁流程击杀 zmserv 及随机名同伴进程
- 与 **jfglzsn**：同属"学生机房"管理家族，about 的退出动作是反制 jfglzsn 保护机制的钥匙
- 与 **przs**：przs 托盘图标点击后启动 about.exe（入口衔接）

## 五、持久化与配置

| 项 | 值 |
|----|----|
| 注册表 | `HKCU\Software\n`（退出密码哈希） |
| 密码算法 | SHA256(明文 + "bfdshgs") 十六进制小写 |
| 随机进程名 | 日期种子生成，用于躲藏与卸载识别 |

## 六、危害总结

- **对用户**：正常途径无法退出家族（需要知道密码），卸载必须走密码验证
- **对抗清理**：解锁流程涉及杀进程/杀服务/改注册表，本质是"受控卸载"——防止用户绕过保护机制
- **典型性**：这是"流氓软件全家桶"的标准组成——**入口（set/przs）→ 驻留（jfglzsn/zmserv）→ 受控退出（about/uninstall）**

> 结论：about 不是独立的威胁，而是家族"退出/解锁"门面；分析价值在于揭示了完整的卸载路径与随机进程名机制。
