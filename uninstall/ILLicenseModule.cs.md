# ILLicenseModule.cs 分析

## 文件作用

保护器（IntelliLock / .NET Reactor 一类）注入的「许可模块」占位类。类里只有两个恒返回常量的
静态方法，**全工程没有任何调用点**，也没有字段和状态。属于混淆器塞进来的纯噪声。

保留它的唯一意义：保持类型表与原始样本一致，方便日后按 Token/类型名对照 IL。

## 类与职责

| 类/模块 | 真实职责 |
| --- | --- |
| `ILLicenseModule` | 保护器占位类，无业务逻辑 |
| `混淆器占位方法_恒真()`（原 `MoveParser`） | `return true`，无调用者、无副作用 |
| `混淆器占位方法_恒假()`（原 `ReadParser`） | `return false`，无调用者、无副作用 |

## 反混淆命名映射

| 混淆名 | 反混淆名 | 说明 |
| --- | --- | --- |
| `ILLicenseModule` | 保留 | 名字本身就像「IntelliLock License Module」，是保护器命名；保留以对齐原始类型表 |
| `MoveParser` | `混淆器占位方法_恒真` | 恒返回 true 的占位方法 |
| `ReadParser` | `混淆器占位方法_恒假` | 恒返回 false 的占位方法 |

## 关键方法与流程

两者都只有一行 `return <常量>;`，不接受参数、不访问静态状态、不抛异常。
反编译时它们是「方法体非空但完全无意义」的典型样本——如果只看方法名会误以为与解析/许可校验有关，
实际参与不了任何流程。

## 恶意行为 / 敏感操作

无直接恶意行为。价值在于「反分析噪声」：

- 增加类型/方法数量，让静态清单看起来更复杂；
- 方法名带 `License`，误导分析者以为有授权校验逻辑。

## IOC / 硬编码

| 类型 | 值 | 用途 |
| --- | --- | --- |
| 类名 | `ILLicenseModule` | 保护器命名痕迹（IntelliLock） |
| Token | 类型 `0x02000011`；方法 `0x06000068`、`0x06000069` | 元数据行号 |
| 返回常量 | `true`、`false` | 仅返回值 |
