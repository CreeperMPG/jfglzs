# uninstall 行为分析

> 所属家族：机房管理助手（jfglzs13.4）· 组件定位：**受控卸载（完整回滚脚本）**
> 分析基于反混淆还原后的代码，非恶意样本运行观察。

## 一、程序概览

`uninstall.exe` 是家族里唯一「做完事就消失」的组件：不装服务、不写自启动、不开网络线程、不常驻。它只做一件事——在已被完全管控的机器上，把管理端当初施加的加固动作逐条反向撤掉，最后重启资源管理器。

| 项 | 值 |
| --- | --- |
| 程序集名 / 根命名空间 | `uninstall` / `WindowsApplication1` |
| 目标框架 / 输出类型 | .NET Framework `v4.5` / `WinExe` |
| 入口 | `WindowsApplication1.Internal.Importer`（`Main` → `My.Application.Run`） |
| 权限清单 | `app.manifest` 的 `requestedExecutionLevel level="requireAdministrator"` |
| 版本 / 程序集 GUID | `1.0.0.0` / `26148b78-26a7-4e21-aa4f-2f2b74167088` |
| 反分析标记 | `[assembly: SuppressIldasm]`；标题、描述、公司、产品、版权全部为空串 |
| 源码构成 | 16 个 `.cs`：2 个窗体、1 个卸载核心、4 个 VB 模板类（`Importer`/`Template`/`Rules`/`Test`）、4 个保护器残留、2 个占位类、2 个 My.Settings 别名层、1 个 `AssemblyInfo.cs` |

真正产生行为的只有三处：

- `Form1.Designer.cs` —— 隐身启动窗，负责算出「今天的进程名」并分流；
- `Form2.Designer.cs` —— 密码闸门 + 强制全屏窗（含重启电脑按钮）；
- `Internal/MappingConfig.cs` —— `卸载核心`，全部删除 / 回滚动作都在这里，`执行卸载()` 约 200 行、23 个阶段。

其余 13 个文件对行为没有贡献：`Internal/IndexerConfig.cs` 是 .NET Reactor 运行时（自实现 MD5、AES 字符串解密、`VirtualProtect` + `WriteProcessMemory` 自修改代码），`Internal/AttributeConfig.cs` 是内嵌程序集加载器（落盘分支会写 `%TEMP%\{资源名}\{短名}.dll`），`Internal/RegistryConfig.cs` 是 IntelliLock 未注册提示，`ILLicenseModule.cs` 与各处 `*Parser` 全是恒真恒假占位方法。

**它反而不是一个「卸载器」**：没有已安装组件清单、没有进度、没有确认对话框、没有日志、没有备份、没有失败回滚。整个卸载过程用户看到的是一个最大化的蓝色窗体，鼠标被锁在 (0,0)-(800,200) 的小方块里。

## 二、界面与交互流程

启动链：`Importer.Main` → `My.Application.Run` → `OnCreateMainForm` 把主窗体定为 `My.Forms.Form1` 单例 → `Form1.Load`。`Importer` 的四个应用级开关是硬编码的：`IsSingleInstance = false`（可多开，同时跑几份卸载器都行）、`EnableVisualStyles = true`、`SaveMySettingsOnExit = true`、`ShutdownStyle = AfterMainFormCloses`。

### Form1：用户看不见的启动窗

| 属性 | 值 |
| --- | --- |
| `ClientSize` | `385 × 224` |
| `FormBorderStyle` / `ControlBox` | `None` / `false` |
| `ShowInTaskbar` / `WindowState` | `false` / `Minimized` |
| `Text` | `卸载` |
| `Timer2.Interval` | `1000` |

`Load` 事件的方法体分三段：

1. **遗留段**：用 `Month(Now) * Day(Now)` 的四个取模（`%7`/`%9`/`%5`/`%3`）按奇偶拼出四个字母赋给窗体 `Name`，再写进 `卸载核心.进程名`。这两行紧接着就被下一段覆盖，是留在原地的废代码（原样保留）。
2. **真正的进程名**：`VBMath.Randomize(月 × 日)` → `Round(Rnd() * 100000 * 3 + 1)`，把十进制最低 5 位各加 `105` 得到 `Chr`，即 5 个落在 `i`..`r` 区间的字母；写入 `卸载核心.进程名`、`进程文件名`（加 `.exe`），并拼出 `候选安装目录 = "C:\Program Files (x86)\" + Mid(进程名, 2, 4)`（目录取后 4 位；本工程没有任何地方读这三个字段中的后两个）。
3. **分流**：读 `HKCU\Software` 的值 `n`。为空 → 直接 `执行卸载()` → `Thread.Sleep(9000)` → `ProjectData.EndApp()`；非空 → `My.Forms.Form2.Show()`，并打开 1 秒定时器。

`Timer2` 的 Tick 只有一句：`if (!Form2.Visible) Form2.Show()`。每秒钟把密码窗重新拉出来一次，用来对抗「把密码窗最小化 / 藏到后台」这种规避手法。

### Form2：密码闸门 + 强制窗

窗体本身：`ClientSize 637 × 407`、`BackColor = SystemColors.Highlight`、`FormBorderStyle.None`、`ShowInTaskbar = false`、`TopMost = true`、`WindowState = Maximized`、`Text = "Form2"`。

| 控件 | 文本 / 属性 | 作用 |
| --- | --- | --- |
| `Label1` | `卸载小助手密码：`（宋体 10.5，白字） | 标题 |
| `TextBox1` | `PasswordChar = '*'`，104×21 | 密码输入 |
| `Button1` | `确定(需10秒)` | 校验并执行卸载 |
| `Button2` | `重启电脑` | `shutdown /r /f /t 0` |
| `Label2` | 空正文，`DarkRed` | 错误提示 |
| `Label3` | `提醒：1、软件有问题请联系QQ：1023411046，下载最新版本请访问：www.jfglzs.com` | 作者联系方式 |
| `Label4` | `2、卸载后记得在硬盘保护系统中创建进度或保存系统。` | 使用提示 |
| `Label_pd` | 四个空格，宋体 26.25 号 | 倒计时占位（双击绑定到空方法 `PatchReader`） |

「确定」的处理顺序：

1. `Len(输入) < 6` → 显示 `密码应该是6位以上的字母或数字，请重新输入！`、清空输入框、返回；
2. 算 `SHA256(Trim(输入) + "bfdshgs")` 的十六进制小写串，与 `HKCU\Software` 的 `n` 做 `CompareString`；不等 → 显示 `密码不正确，请重新输入！`、清空、返回；
3. 相等 → 禁用按钮、清提示、鼠标改沙漏、调用 `卸载核心.执行卸载()`、恢复鼠标；
4. 读 `HKCU\Control Panel\Desktop` 的 `Wallpaper`，若路径含「壁纸」二字（说明被管理端换过）就改回 `C:\Windows\Web\Wallpaper\Windows\img0.jpg`（写 `Wallpaper`、`WallpaperStyle = "2"`，再 `SystemParametersInfo(20, 0, 路径, 3)`）；
5. `ClipCursor` 把鼠标锁到整屏范围 → `Thread.Sleep(9000)` → `ProjectData.EndApp()`。

### 强制与对抗

| 机制 | 实现 |
| --- | --- |
| 关不掉 | `FormClosing` 无条件 `e.Cancel = true`（`×`、Alt+F4、任务管理器「结束任务」全部无效） |
| 藏不掉 | 1 秒定时器每 Tick 重新 `TopMost = true` |
| 鼠标出不去 | 每 Tick `ClipCursor` 到 `(0,0)-(800,200)` |
| 吵闹催促 | 定时器计数 ≥ 5 后，每 Tick `Beep(2000, 500)` |
| 立刻重启 | `Interaction.Shell("shutdown /r /f /t 0", MinimizedFocus, false, -1)` —— 不等待、不保存任何东西 |
| 结束自身 | `ProjectData.EndApp()`（VB 的 `End`，直接终止进程） |

两处接不上的死代码：`VisitReader` 会 `Process.Start("http://www.jfglzs.com")`，但 Designer 里根本没有 LinkLabel；`WallpaperStyle` 枚举（`Tiled = 1`、`Centered`、`Stretched = 6`）与 `configConfig`/`serviceConfig`/`stubConfig` 常量从未被使用。

## 三、核心行为

`执行卸载()` 的顺序就是它的行为清单。原版整段处在 VB 的 `On Error Resume Next` 之下——每条语句出错只被吞掉、继续下一条；反混淆后逐条 `try/catch`，这也是解读这份代码时最重要的一条语义。

| # | 阶段 | 具体动作 |
| --- | --- | --- |
| 1 | 定位安装目录 | 读 `HKLM\SOFTWARE\MICROSOFT\WINDOWS\CURRENTVERSION\RUN` 的 `prozs`，为空再读 `WOW6432NODE` 同名键；`Mid(值, 1, Len - 9)` 去掉末尾 `\przs.exe`（9 个字符）得到安装目录 |
| 2 | 杀进程 | `do { 杀随机名进程; 杀 jfglzsn } while (两者都没杀到)` |
| 3 | 清缓存目录 | `C:\windows\jf` 下 `jfglzsn.dat`、`przs.dat`、`zmserv.dat` 先 `SetAttributes(Normal)` 再删，最后删目录 |
| 4 | 清安装目录 | `jfglzsn.exe`、`zmserv.exe`、`przs.exe`、`yl.wav`，同样先去只读再删 |
| 5 | 放开 CMD / 注册表 | `DisableCMD = 0`、`DisableRegistryTools = 0`、`NoRun = 0` |
| 6 | 特殊目录 | 读 `HKCU\Software\jfglzs` 的 `dzjs`，`Mid(值, 1, Len - 16)` 去掉末尾 16 位校验串，对该目录下 `SpecialSet.exe` 去只读 |
| 7 | 停服务 | `net stop zmserv`（隐藏窗口、等待返回）→ `Sleep 3000` → `Kill` `zmserv` 进程 |
| 8 | 删自启动 | `Run` 与 `WOW6432NODE\Run` 下的 `prozs`、`jfglzsn` 四个值 |
| 9 | 开机菜单 / USB | `cmd /c bcdedit /set {bootmgr} displaybootmenu yes`（最小化、不等待）；`usbstor` 的 `Start = 3` 写四处（`CurrentControlSet`、`ControlSet001`~`003`） |
| 10 | 允许锁屏 | `DisableLockWorkstation = 0` |
| 11 | 删密码标记 | `HKCU\Software` 下的 `n`、`dtmm`、`czmm` |
| 12 | 删配置根 | 整个 `HKCU\Software\jfglzs`（先 `OpenSubKey` 判存在再 `DeleteSubKey`） |
| 13 | 删 IFEO 劫持 | 21 条 `Image File Execution Options\{进程名}`（见下表） |
| 14 | 删浏览器策略根 | `Software\Policies\Google\Chrome`、`Software\Policies\Microsoft\Edge`（整键删） |
| 15 | 还原 hosts | `hosts`、`hosts-bak`、`C:\Windows\System32\drivers\etc` 去只读 → `File.Copy(hosts-bak, hosts, true)` |
| 16 | 恢复浏览器/资源管理器策略 | 14 个值（见第五节表） |
| 17 | 删服务 | `sc delete zmserv`（隐藏、等待） |
| 18 | 导入还原脚本 | 把安装目录的 `huifu.wav` 复制成 `huifu.reg`（`huifu.wav` 其实是 .reg 文本，改扩展名躲检测）→ `regedit.exe /s <安装目录>\huifu.reg` → `Sleep 2000` → 删 `huifu.reg`、`yl.reg` |
| 19 | 恢复界面 | `NoTrayContextMenu = 0`、`ShowTaskViewButton = 1` |
| 20 | 恢复关机行为 | 删 `AutoEndTasks`；`HungAppTimeout = "3000"`、`WaitToKillAppTimeout = "10000"`（字符串）；删 `StartupDelayInMSec`；`C:\Program Files\Microsoft Games` 去只读 |
| 21 | 恢复网络/提示 | `Tcpip6\Parameters\DisabledComponents = 0`、`TabletTip\1.7\TipbandDesiredVisibility = 1` |
| 22 | 第二轮清理 | 再杀一轮随机名进程与 `jfglzsn`，再删一遍缓存目录与安装目录（这次多删 `huifu.wav`） |
| 23 | 重启外壳 | `C:\Windows\Microsoft.NET` 去只读 → `Sleep 2000` → 杀掉所有 `explorer.exe` → `Process.Start("explorer.exe")` |

### 进程查杀的判定方式

`Process.GetProcessesByName(name)` 取到空数组后 `[0].Kill()` 会抛越界异常、被 `catch` 吞掉；`do/while` 的条件是「两组的 `Length` 都等于 0」。也就是说它**不是**用 `Length > 0` 判断进程是否存在，而是用「Kill 炸了＝进程不在了」来驱动循环。原样保留，改写成正常判空会改变退出时机。

清杀目标共四种：随机 5 字母名（`przs` 的当日进程名）、`jfglzsn`、`zmserv`、`explorer`（最后一种只杀不重启自身）。第二轮重复是有理由的——第 18 步 `regedit` 导入后守护进程可能又被拉起来，注释里写明了这一点。

### 文件清理的两个前提

- 所有删除前都先 `File.SetAttributes(路径, FileAttributes.Normal)`：管理端把 `jf` 缓存、`huifu.wav`、安装目录里的 exe 都加过 Hidden/System/只读，不去属性删不掉。
- 删除清单只有 5 个文件：`jfglzsn.exe`、`zmserv.exe`、`przs.exe`、`yl.wav`、`huifu.wav`（外加临时生成的 `huifu.reg`、`yl.reg`）。据家族 README，同目录还有 `set.exe`、`about.exe`、`uninstall.exe`、`regini.exe`、`hmd_local.txt`、`hosts`、`zy\` 假浏览器目录等——**这些都不在删除范围内**，卸载后安装目录并不干净。

### 路径退化与静默中断

两个值得写进报告的实现细节：

- 安装目录完全依赖 `Run\prozs` 的值。该值缺失时 `Strings.Mid("", 1, -9)` 抛异常被吞掉，`安装目录` 保持 `Nothing`，后续 `Operators.ConcatenateObject(安装目录, "\jfglzsn.exe")` 会退化成 `<盘符>:\jfglzsn.exe` 这种**当前驱动器根目录**路径——删除动作落到了与安装目录无关的位置。
- `do/while` 的条件在 `try/catch` 之外。如果某次 `GetProcessesByName` 抛异常，`进程组` 保持 `null`，`while` 判空时会抛 `NullReferenceException`；而 `执行卸载()` 的调用点（`Form1` 与 `Form2`）外面只有一层 `catch { }`——于是**后面全部 21 个阶段被静默跳过**，用户在界面上看不出任何区别。

### 命令执行一览

| 命令 | 窗口样式 | 是否等待 |
| --- | --- | --- |
| `net stop zmserv` | `Hide` | 等待 |
| `cmd /c bcdedit /set {bootmgr} displaybootmenu yes` | `MinimizedFocus` | 不等待 |
| `sc delete zmserv` | `Hide` | 等待 |
| `regedit.exe /s <安装目录>\huifu.reg` | `Hide` | 等待 |
| `shutdown /r /f /t 0`（Form2 按钮） | `MinimizedFocus` | 不等待 |
| `Process.Start("explorer.exe")` | — | — |

全部走 `Interaction.Shell`（VB 的 `Shell`，不是 `Process.Start`），所以「等待返回」的语义与 `Shell` 一致；第 4 个参数 `-1` 是 `Timeout`（不设超时上限）。

## 四、与其他组件的关系

`uninstall` 的回滚清单几乎就是其它四个组件的动作清单的镜像。逐条对照（对照依据：本工程常量 + 兄弟工程里的同名字符串）：

| 兄弟组件 | 本工程对它的动作 / 依赖 |
| --- | --- |
| `set.exe`（管理端设置） | 写下的 `Run\prozs` / `Run\jfglzsn` 被本组件读取与删除；`hosts-bak` 是 `set` 改 hosts 前留的备份，本组件用它覆盖回 `hosts`；`huifu.wav`（实为 .reg）由 `set` 释放、由本组件导入后删除；`HKCU\Software\jfglzs\dzjs` 由 `set` 写入（那里是电子教室学生端路径），本组件读出目录后只对其中 `SpecialSet.exe` 去只读；`C:\windows\jf\*.dat` 是 `set` 把三个 exe 改名藏起来的副本，本组件整目录删除 |
| `przs.exe`（主控驻留） | 当日 5 字母随机名进程 + 安装目录里的 `przs.exe` + `jf` 下的 `przs.dat`；本组件的 `候选安装目录 = "C:\Program Files (x86)\" + Mid(进程名, 2, 4)` 正好对应 `przs` 自我迁居的「4 字母目录 + 5 字母 exe」结构（本工程只算不用） |
| `jfglzsn.exe`（核心调度） | 进程名 `jfglzsn`、`jf` 下的 `jfglzsn.dat`、`Run\jfglzsn`；本组件从第 2 步开始循环查杀，第 20 步再杀一轮 |
| `zmserv.exe`（看门狗服务） | 服务名 `zmserv`：`net stop` → `Sleep 3000` → `Kill` → `sc delete`；`jf` 下的 `zmserv.dat` 一并删 |
| `about.exe`（退出解锁） | 与本组件共用同一套密码方案：`SHA256(明文 + "bfdshgs")` 与 `HKCU\Software\n` 比对。分工不同——`about` 只做「退出/临时解除管控」，本组件做「完整删除 + 恢复默认」 |

**两边算法逐字相同**：本工程 `Form1.Load` 生成随机进程名的算式（`VBMath.Randomize(月 × 日)` → `Round(Rnd() * 100000 * 3 + 1)` → 每位 `% 10 + 105` → `Chr`）与 `zmserv` 服务 `OnStart` 里的受监视进程名生成算式完全一致（连「先拼一版 4 字母、随后被覆盖」的废代码都一样）。也就是说：**卸载器自己会算出看门狗正在盯的那个名字**，这是它能定点杀掉「当前日期那一份」进程的原因；名字每天换，静态写死进程名是杀不掉的。

**时序上的一个竞态（静态推断）**：`zmserv` 每 5 秒检查一次，连续 16 次（约 80 秒）看不到 `jfglzsn` 与当日随机名进程就强制关机（`RtlAdjustPrivilege` + `NtShutdownSystem` + `shutdown /s /f /t 0`）。而本组件的顺序是**先杀进程（第 2 步）、后停服务（第 7 步）**，中间还有 `Sleep 3000`、`Sleep 2000`、`Sleep 9000`。正常机器上 80 秒窗口足够跑完，但任何一步卡住（`regedit` 弹框、硬盘保护系统拦截、杀软阻塞），卸载过程本身就可能撞进关机判定。这一段属于基于两个组件代码的推断，未做运行验证。

## 五、持久化与配置

**本工程自身零持久化**：不写任何 `Run` 键、不装服务、不释放文件到系统目录、不建计划任务。唯一临时落盘是第 18 步生成的 `huifu.reg`（用完就删），以及保护器遗留的 `%TEMP%\{资源名}\{短名}.dll` 分支（只在 `Assembly.Load(byte[])` 失败时触发，属于壳的行为）。

它做的是**反向持久化**：把兄弟组件留下的自启动、服务、策略、劫持项逐一拆除。

### 读取的配置

| 项 | 值 | 含义 |
| --- | --- | --- |
| `HKCU\Software` | `n` | 卸载密码摘要（`SHA256(明文 + "bfdshgs")` 十六进制小写）；为空＝没设密码，直接免密卸载 |
| `HKCU\Software\jfglzs` | `dzjs` | 目录串（末尾带 16 位校验串），取其 `SpecialSet.exe` 去只读 |
| `HKLM\SOFTWARE\MICROSOFT\WINDOWS\CURRENTVERSION\RUN` | `prozs` | 自启动命令，形如 `<安装目录>\przs.exe`；去掉末尾 9 字符即安装目录 |
| `HKCU\Control Panel\Desktop` | `Wallpaper` | 当前壁纸路径；含「壁纸」二字就换成系统默认图 |

### 写入与删除的系统项

| 项 | 值 | 含义 |
| --- | --- | --- |
| `HKCU\Software\Policies\Microsoft\Windows\System` | `DisableCMD = 0` | 恢复命令提示符 |
| `HKCU\Software\Microsoft\Windows\CurrentVersion\Policies\System` | `DisableRegistryTools = 0`、`DisableLockWorkstation = 0` | 恢复注册表编辑器、允许锁屏 |
| `HKCU\Software\Microsoft\Windows\CurrentVersion\Policies\Explorer` | `NoRun = 0`、`NoFolderOptions = 0`、`NoTrayContextMenu = 0` | 恢复「运行」、文件夹选项、托盘右键菜单 |
| `HKLM\SYSTEM\{CurrentControlSet,ControlSet001,ControlSet002,ControlSet003}\Services\usbstor` | `Start = 3` | 恢复 U 盘存储驱动（管理端改成 4＝禁用） |

## 六、危害总结

单看这一个文件，它不像木马：没有网络、没有 C2、不上传任何数据、不留后门、不盗取凭据。它的危害是**「持有管理员权限的破坏性动作被包在一个没有任何审计的壳里」**，具体有五点：

1. **以管理员权限静默导入外部 .reg**。`regedit.exe /s <安装目录>\huifu.reg` 走的是卸载器自己的管理员令牌（清单要求 `requireAdministrator`），而源文件 `huifu.wav` 就在安装目录里。只要安装目录对普通用户可写（装到非默认位置、ACL 被放宽、或盘符权限松），这就成了一个「被替换一个音频文件 = 以管理员身份写任意注册表」的投递面。
2. **删除目标不是常量**。安装目录完全来自 `HKLM\...\Run\prozs` 的值，任何人改掉这个值，卸载器就会带着管理员权限去那个目录删 `jfglzsn.exe` / `zmserv.exe` / `przs.exe` / `yl.wav` 一类的文件；值缺失时还会退化成 `<盘符>:\` 根目录路径。删除范围由可写注册表决定，而不是由校验过的安装信息决定。
3. **鉴权形同虚设，且存在免密通道**。密码是单轮 `SHA256(明文 + "bfdshgs")`、固定盐、无迭代、无服务端校验，拿到 `HKCU\Software\n` 即可离线爆破；反过来，把 `n` 删掉（本组件自己第 11 步就删）会让程序进入「无密码直接卸载」分支——整个密码闸门只保护「不知道密码的普通用户」，不构成任何真实防护。
4. **强制中断用户的一切操作**。`FormClosing` 取消关闭、`TopMost` 保持置顶、`ClipCursor` 把鼠标锁进 800×200、`Beep(2000, 500)` 每秒催促、「重启电脑」按钮直接 `shutdown /r /f /t 0`（不保存任何未存盘内容）。用户在卸载过程中没有任何退路。
5. **失败即静默**。每条语句独立吞异常，中途某步失败（权限不足、硬盘保护系统拦截、注册表被锁）不会提示、不会回滚、不会记日志；再加上第三节说的「`while` 判空异常会让后续阶段整体跳过」，用户完全可能在一个「看起来跑完了」的卸载之后，机器仍处在半管控半放开的状态——`usbstor` 已恢复、`Run` 键已删、但服务还在、IFEO 还在、hosts 还是被劫持的版本。

需要强调的定性：`uninstall` 是这套管控软件的**合法出口**（管理员输密码主动触发的完整回滚），而不是独立的恶意载荷。但它的能力集与破坏性工具完全重合——任意杀进程、删目录、改 `HKLM`、删服务、执行系统命令、强制重启——换成另一组常量就是一个破坏性工具。分析时应按「高风险系统操作集合」对待，而不是按「卸载器」从轻处理。
