# przs 行为分析

> 所属家族：机房管理助手（jfglzs13.4）· 组件定位：**主控驻留 + 双锁屏 + 文件监控**
> 分析基于反混淆还原后的代码，非恶意样本运行观察。

## 一、程序概览

`przs.exe` 是整套"学生机房管理助手"里**唯一常驻的学生侧主控**：它没有设置界面，启动后立刻隐身，
把自己复制到 `C:\Program Files (x86)` 下的随机目录，然后靠一组定时器 + 一个 `FileSystemWatcher`
长期"看管"这台机器——看守伴生进程、回写被改掉的浏览器/U 盘策略、恢复被删的 hosts、按扩展名删掉
学生新建的文件，并在违规累计到阈值时弹出**全屏锁屏窗**要密码。

| 项 | 值 |
| --- | --- |
| 程序集名 / 命名空间 | `przs` / `przs`（内部类型都在 `OZxTKXuvsl9D34LWhP.Internal`） |
| 语言 / 框架 | VB.NET 编译产物（C# 反编译），.NET Framework **v4.5**，`WinExe` |
| 入口点 | `OZxTKXuvsl9D34LWhP.Internal.Val.CallVal`（`[STAThread]`，csproj `StartupObject` 写死） |
| 主窗体 | `Form1`——隐藏运行；`Val` 构造函数里 `IsSingleInstance = false`，**允许双开** |
| 权限 | `app.manifest` 里 `requestedExecutionLevel level="requireAdministrator"`——**必须提权运行** |
| 规模 | 19 个 `.cs`；主文件 `Form1.Designer.cs` 1261 行、`Form2.Designer.cs` 581 行 |
| 程序集元数据 | 版本 `1.0.0.0`、GUID `ca2000e9-458b-4ab6-989c-c47028ea8888`、`[SuppressIldasm]`、作者字段全空 |
| 网络 | **本工程代码里没有任何 HTTP/Socket/WebClient 调用**，不联网（配置与黑名单下发都在别的组件） |

## 二、界面与交互流程

### 1. 第一会话：用户什么都看不到

进程一启动，`Form1.Load` 做的第一件事是 `Hide()`，随后判断 `Application.StartupPath` 里是否含
`C:\Program Files (x86)`。**不含**（首次运行、从安装目录或被改名后运行）就走迁居分支：

1. 托盘图标先设 `Visible = false`；
2. 建目录、删旧副本、复制自身、给目录和副本都加上 `Hidden | System`；
3. 启动副本，本进程 `ProjectData.EndApp()` 自杀。

这一步用户完全不可见：无窗口、无托盘、无提示。窗口标题在分支之前就被改成随机 3 个字符
（初值是伪装的 `word`）。

### 2. 稳定驻留期可见的界面

| 界面 | 触发条件 | 外观 | 交互 |
| --- | --- | --- | --- |
| 托盘图标 | 常驻 | 文本 `学生机房管理助手`，无右键菜单 | 单击 → 启动 `<程序所在目录>\about.exe` |
| `bianhao` 机号窗 | 注册表 `HKCU\Software\jfglzs\bianhao = on` | 无边框、透明底、右上角 `(屏宽-350, 100)`、黑体 65.25pt 橙字 | 显示计算机名末 6 位；悬停时第二行显示"由机房管理助手自动生成" |
| `Form3` "提醒"窗 | 文件被删 / 策略被改 / hosts 被删 | 蓝底（`SystemColors.Highlight`）、`1248×559`、居中、`TopMost`、标题 `提醒`；两行宋体 15.75pt 红字 + 一行未设样式的小字 | 无按钮，只能被 Form1 关掉 |
| `Form2` 锁屏窗 | 违规计数到阈值（见 3.2、3.7） | 无边框 + 最大化 + `TopMost` + 不显示在任务栏；顶部一行"退出小助手密码："+ 密码框 + `确 定` + `重启电脑` | 关不掉；输密码可退出；右上角有空白的隐藏标签（后门） |
| `Form4` 锁屏窗 | —— | 高亮蓝底、`1023×686`、`TopMost` | **本工程内无人 `Show()`**（见 3.7） |

> 注：文件级分析里把 `Form3` 描述成"无边框 + 最大化"，源码并未设置 `FormBorderStyle` / `WindowState`，
> 实际是一个**居中的、带标题栏的 1248×559 置顶窗**。本文按源码写。

### 3. 被管控者视角的完整流程

1. 学生在桌面/下载目录/任意盘符根目录**新建 `.exe`、`.reg`、`.bat`、`.msi`…** →
   `FileSystemWatcher` 立刻删除，并弹出 `Form3`：
   "本电脑禁止创建新的exe文件，再次操作会锁屏！" / "老师请先退出小助手，重新安装软件。你也可重新设置：允许（不建议）"
   / "刚刚删除文件：<路径>"；
2. 继续尝试 → 三个计数器各自累加：`jfglzsn` 被杀次数、hosts 被删次数、禁止下载项被改次数；
3. 任一计数越线（hosts > 5、注册表 > 15、jfglzsn 被终止 ≥ 40）→ 弹出 `Form2`：
   全屏、置顶、鼠标被 `ClipCursor` 锁进左上角 `(0,0)-(500,100)`、第 5 秒起 `Beep(2000, 500)` 长鸣；
4. 关不掉（`FormClosing` 里 `e.Cancel = true`），只能：
   - 点 `重启电脑` → `shutdown /r /f /t 0`（强制重启，不提示保存）；
   - 或输入 ≥6 位密码 → 与 `HKCU\Software\n` 里的 `SHA256(输入 + "bfdshgs")` 比对；
5. 密码正确 → 隐藏的"退出流程"：循环杀 `jfglzsn` → 放开 `DisableCMD` → `net stop zmserv` → 等 3 秒 →
   杀 `zmserv` → 解除鼠标锁定 → `ProjectData.EndApp()`（przs 自身退出）。

### 4. 隐藏交互

`Form2` 右上角有个 24pt、`Text = "     "`（5 个空格）、背景与窗体同为高亮蓝的标签 `Label_pd`，
肉眼看不见。**双击**它会触发后门（见 3.8）。

## 三、核心行为

### 3.1 自我迁居（启动即自复制 + 自杀）

| 步骤 | 细节 |
| --- | --- |
| 算"程序所在目录" | 读 `HKLM\SOFTWARE\MICROSOFT\WINDOWS\CURRENTVERSION\RUN` 的 `prozs`，为空再读 `…WOW6432NODE…` 同名值；**把值末尾 9 个字符（`\przs.exe`）截掉**得到目录 |
| 造随机名（第一轮，被覆盖） | `月 × 日` 分别 `%7 %9 %5 %3`，偶数按 `a+余7, b+余9, e+余5, c+余3`、奇数换序 → 4 个小写字母 |
| 造随机名（第二轮，生效） | `VBMath.Randomize(月×日)` → `Rnd()*100000*3+1` 四舍五入 → 逐位 `%10 + 105`（ASCII 105~114 = `i`~`r`）→ **5 个字符** |
| 目标路径 | 目录 `C:\Program Files (x86)\<5 位名的第 2~5 位>`；文件 `<5 位名>.exe`；窗口标题 = 第 1~3 位 |
| 落地 | 建目录 → 副本 `SetAttributes(Normal)` → `Delete` 旧文件 → `File.Copy(Application.StartupPath\przs.exe, 目标, true)` |
| 隐身 | 目录和副本都加上 `Hidden` + `System` 两个属性 |
| 交接 | 副本进程名未在跑就 `Process.Start(副本)`；随后 `ProjectData.EndApp()` |

关键副作用：**副本名由"月×日"决定，同一天全机房同名、可提前算出**；源文件名被写死成 `przs.exe`
（不是自身真实文件名），所以从别的文件名启动时复制会失败。整个迁居**不写任何自启动项**——
它假定自启动已经由外部（安装器 / `set.exe`）写好了 `prozs`。

### 3.2 七个定时器与相互启用关系

| 定时器 | 间隔 | 何时启用 | 行为 |
| --- | --- | --- | --- |
| `Timer_main` | 10000 ms | 初始化组件里就 `Enabled = true`；跑完自停 | 打开 `Timer1`；读 `games_jianche=on` → 打开 `Timer_youxi`；读 `bianhao=on` → `Show()` 机号窗 |
| `Timer1` | 3000 ms | **由 `Timer_main` 打开**（即程序启动 10 秒后才开始看护） | 见 3.3 |
| `Timer2` | 1000 ms | 任一违规阈值触发后打开 | `Form2` 不可见就 `Show()`——保证锁屏窗一直挂在最前面 |
| `Timer_jianchahosts` | 15000 ms | 初始化组件里就启用 | hosts 守护（3.4） |
| `Timer_jzxz` | 5000 ms | `Load` 里 `xiazai=off` 时启用 | 下载限制回写（3.5） |
| `Timer_youxi` | 30000 ms | `games_jianche=on` 时启用 | 游戏限制回写（3.5） |
| `Timer4` | 1000 ms | **从未启用、也没挂事件** | 死代码 |

所有处理器共用同一套反混淆后的骨架：**每条语句各自 `try { … } catch { }`**——对应原版
`On Error Resume Next`（出错丢掉、继续下一条），因此注册表/进程/文件任一失败都不会中断整轮检查。

### 3.3 看护 `jfglzsn` 进程

1. `Process.GetProcessesByName("jfglzsn")` 非空 → 什么都不做；
2. 为空 → 计数 `+1`（`checked`）；
3. `<程序所在目录>\jfglzsn.exe` 不存在、而 `C:\windows\jf\jfglzsn.dat` 存在 → 把 `.dat` 复制成 `.exe`；
4. `Process.Start` 启动它（走 `NewLateBinding.LateCall`，保留 VB 迟绑定语义）；
5. 计数 `≥ 40` → `Form2` 文案 `进程j被多次终止或文件会被杀毒软件（如win10自带的defender）清除！` + 显示 + 打开 `Timer2`。

即：**przs 是 `jfglzsn` 的复活器**，杀软每清一次就在 3 秒内被拉起来一次，还得杀到第 40 次才轮到锁屏。

### 3.4 hosts 守护

- 目标文件 `C:\Windows\System32\drivers\etc\hosts`，备份是**路径后加一个 `"2"`**，即 `…\etc\hosts2`；
- 15 秒一轮：文件不存在 → 计数 `+1`、置"正在提示"标志；备份存在就 `File.Copy(hosts2, hosts, true)` 覆盖恢复，
  并弹 `Form3`：`hosts文件被删除！现在恢复。`；
- 计数 `> 5` → 关 `Form3`，改弹 `Form2`：`hosts文件多次被删除或备份文件不存在！`；
- 一旦 hosts 又存在 → 关 `Form3`、清标志（不会主动改 hosts 内容，只保证"文件在"）。

### 3.5 策略强制回写

**下载限制（5 秒一轮）**

三个探针值只要有一个不是字符串 `"3"` 就判定"被改了"：

- `HKCU\SOFTWARE\Microsoft\Windows\CurrentVersion\Internet Settings\Zones\3` → `1803`
- `HKLM\SOFTWARE\Policies\Google\Chrome` → `DownloadRestrictions`
- `HKLM\SOFTWARE\Policies\Microsoft\Edge` → `DownloadRestrictions`

被改了 → 计数 `+1`，`> 15` 就只弹 `Form2`（`你多次修改了注册表的禁止下载项！` + `请重新启动电脑！`）并 `return`；
否则先回写 12 个值：

| 注册表键 | 值名 | 写入 |
| --- | --- | --- |
| `HKCU\SOFTWARE\Microsoft\Windows\CurrentVersion\Internet Settings\Zones\3` | `1803` / `2200` | `3` / `1`（DWord） |
| `HKCU\Software\Policies\Microsoft\Internet Explorer\Restrictions` | `NoBrowserSaveAs` | `1` |
| `HKLM\SOFTWARE\Policies\Microsoft\Edge` | `DownloadRestrictions` / `SaveAs` / `DeveloperToolsAvailability` | `3` / `0` / `2` |
| `HKLM\SOFTWARE\Policies\Google\Chrome` | `DownloadRestrictions` / `SaveAs` / `DeveloperToolsAvailability` | `3` / `0` / `2` |
| `HKLM\SOFTWARE\Policies\Mozilla\Firefox` | `DisableDownloads` / `BlockAboutDownloads` / `DeveloperToolsAvailability` | `1` / `1` / `2` |

然后**杀进程 + 重启外壳**：`chrome`、`msedge`、`firefox`、`iexplorer`、`explorer` 全部 `Kill()`，
再 `Process.Start("explorer")`——等于把用户正在开的所有资源管理器窗口强行关掉重开，
最后弹 `Form3`：`你违规修改了注册表的禁止下载项！` / `现在助手强制恢复！`。

**游戏限制（30 秒一轮）**

`HKLM\SOFTWARE\Policies\Google\Chrome\AllowDinosaurEasterEgg` 或
`HKLM\SOFTWARE\Policies\Microsoft\Edge\AllowSurfGame` 任一不为 `0` → 写回 `0`、杀 `chrome` / `msedge`、
弹 `Form3`：`你违规修改了注册表的禁止游戏项！` / `现在助手强制恢复！`。

**U 盘禁用（只在 Load 时判一次）**

`usb_jianche=on` 且 `HKLM\SYSTEM\CurrentControlSet\Services\usbstor` 的 `Start ≠ 4` →
`CurrentControlSet`、`ControlSet001`、`ControlSet002`、`ControlSet003` **四处全写 `Start = 4`**
（4 = 禁用启动，插 U 盘也不加载存储驱动）。

### 3.6 文件监控与删除（最狠的一支）

`监听目录(string)` 对每个存在目录 new 一个 `FileSystemWatcher`：`Filter = "*.*"`、
`NotifyFilter = FileName | LastWrite`；**桌面额外开 `IncludeSubdirectories`**，其它目录不开。
挂在哪个事件由两个开关决定：`gaowei`（默认 `2`）`≠ 1` 就挂 `Created` + `Changed`；
`xiazai = "off"`（默认值）才挂 `Renamed`。

监视范围（逐个 `Directory.Exists` 通过才挂）：

- `C:\Users\<用户名>\Downloads`（`Environment.UserName` 拼）；
- 桌面（`SpecialFolder.Desktop`）、我的文档（`SpecialFolder.Personal`）；
- `Environment.GetLogicalDrives()` 的**每一个盘符根目录**；
- `d:\` `e:\` `f:\` `c:\` 依次探测的 `360安全浏览器下载` 与 `360极速浏览器下载`（名字来自
  `Proccesor.安全浏览器目录名` / `极速浏览器目录名` 两个静态字段）；
- `D:\ChromeCoreDownloads`、`C:\Windows\Microsoft.NET\Framework\v4.0.30319`。

处理规则（`Created` / `Changed`）：

| 命中扩展名 | 处理 |
| --- | --- |
| `.exe` / `.com` | 同名 `foo.cpp`（`.com` 用 `foo.cp`）存在且 `gaowei=2` → **放行**（白名单约定）；否则死循环：按"无扩展名文件名"取同名进程、主模块路径与事件路径一致就 `Kill()` → `Sleep(500)` → `SetAttributes(Normal)` → `Delete` → 文件还在就重来。删成后弹 `Form3`：`本电脑禁止创建新的exe文件，再次操作会锁屏！` |
| `.reg` `.bat` `.cmd` `.vbs` `.vbe` `.scr` `.dll` `.ps1` `.pif` | `SetAttributes(Normal)` + `Delete` + `Sleep(200)`，连做 3 次；`高危文件删除计数++`；弹 `Form3`：`本电脑禁止创建新的reg、bat等高危文件，再次操作会锁屏！` |
| `.msi` | 路径里含 `config.msi` 就放过（Windows Installer 临时目录）；否则连删 3 次 + 弹 `Form3`：`本电脑禁止创建新的msi等高危文件！` |
| 其它任意扩展名 | `Sleep(500)` 等写完 → 打开读前 2 字节 → `77 90`（`MZ`）就当作改名伪装的 PE：按**带扩展名的文件名**取进程（这一支用 `GetProcessesByName("foo.exe")`，实际匹配不到）→ 归一化属性 → 删 → 文件还在就重试；删成后弹 `Form3`：`本电脑禁止创建新的exe、dll变相文件，再次操作会锁屏！` |

`Renamed` 事件（`xiazai="off"` 时才有）：扩展名命中
`.zip .rar .7z .arj .exe .com .msi .reg .bat .cmd .vbs .vbe .scr .dll .ps1 .pif` →
`Delete` + `Sleep(200)` 连做 3 次 → `Form3` 三行文案
（`本电脑禁止下载安装软件，再次操作会锁屏！` / `如果确有需要，请老师来退出小助手。` / `刚刚删除文件：<路径>`）。

实现细节：两个处理器开头都先 `if (InvokeRequired) { BeginInvoke(自己); return; }`——事件被搬回 UI 线程执行，
所以里面所有 `Sleep(200/500)` 与"文件还在就重试"的 `while` 循环**都会卡住界面线程**；
被占用的文件（例如正在运行的 exe）会让循环永不退出。

### 3.7 锁屏与"退出"

**Form2（真实生效的一把锁）**：无边框 + `Maximized` + `TopMost` + `ShowInTaskbar=false`；
`Timer_frm2` 每秒：`TopMost = true` → `ClipCursor(0,0,500,100)` → 计数 ++ → `≥5` 后每秒 `Beep(2000, 500)`；
`FormClosing` 无条件 `e.Cancel = true`。

**Form4（本工程内的死代码）**：同样是全屏 + `ClipCursor(0,0,800,100)` + 蜂鸣，但
`窗体关闭_判断是否允许` 只看静态字段 `Proccesor.锁屏中禁止关闭`，而**本程序集内没有任何地方把它置 `true`，
也没有任何地方 `Show()` 这个窗体**。所以"双锁屏"在本工程里实际只有 Form2 一把是真能用的，
Form4 是可以直接关掉（关掉时还会顺手把 `ClipCursor` 恢复全屏）的摆设。

**退出流程**（密码正确后，`退出小助手_停服务杀进程`）：

1. `while (true)`：取 `jfglzsn` 进程数组 → `[0].Kill()` → 数组长度 `== 0` 就 `break` → 否则 `Sleep(500)`；
   （进程不存在时 `[0]` 越界，原版靠 `On Error Resume Next` 吞掉，这里靠 `try/catch` 保留同样行为）
2. `HKCU\Software\Policies\Microsoft\Windows\System` 的 `DisableCMD` 写 `0`（放开命令提示符）；
3. `Interaction.Shell("net stop zmserv", Hide, true, -1)`——停服务并等它跑完；
4. `Thread.Sleep(3000)`，再 `Kill` `zmserv` 进程；
5. `ClipCursor` 恢复成整屏矩形，`ProjectData.EndApp()` 结束自己。

注意它**只停服务、杀进程、退出自己**：不删迁居副本、不删 `prozs` 自启动项、不改任何策略，
所以下次开机照样回来（这是"退出"，不是"卸载"）。

### 3.8 后门（Form2 的隐藏标签）

双击那个看不见的 `Label_pd`：

1. `Label2.Text = "ngfxd568bdh158" + pc_num() + "8bsdg45ybfdhg"`——中间那段是
   `COMPUTERNAME` 最后一个字符的 ASCII（环境变量为空时取 `88`），即**每台机器不同的"暗号"**；
2. 把密码框里的**明文**写进 `HKCU\Software\dtmm`（String）；
3. 把 `SHA256("111111" + "bfdshgs")` 写进 `HKCU\Software\czmm`——即"把密码重置成 `111111`"；
4. `Process.Start(<程序所在目录>\yz.exe)`——本工程的第三个伴生程序。

一处值得记的偏差：真正的密码校验读的是 `HKCU\Software\n`，而后门写的是 `czmm`，
**所以单靠这个后门并不能直接把本组件的退出密码改成 111111**，除非家族的其它组件（读 `czmm` 的那个）配合。

### 3.9 进程查杀清单

| 目标 | 场景 |
| --- | --- |
| `chrome`、`msedge`、`firefox`、`iexplorer` | 下载限制/游戏限制被改后的"强制恢复" |
| `explorer` | 同上，杀完立刻 `Process.Start("explorer")` 重启外壳 |
| 与新建文件"同名且主模块路径一致"的任意进程 | 文件拦截里删 `.exe`/`.com`/伪装 PE 前先解锁 |
| `jfglzsn` | 退出流程（循环杀到进程数归零） |
| `zmserv` | 退出流程（`net stop` 之后再杀） |

一句话：przs 不负责"安装"，也不负责"卸载"——它只是**装好之后长期蹲守的那一层**：
保住 `jfglzsn`，把策略按住不许人改，把学生新下的文件删掉，撑不住就锁屏。

## 六、危害总结

| 危害 | 具体表现 | 严重度 |
| --- | --- | --- |
| **驻留与自我隐藏** | 复制到 `C:\Program Files (x86)\<随机>\<随机>.exe` 并加 `Hidden + System`；进程无窗口、不进任务栏、托盘伪装成"学生机房管理助手"；由"月×日"种子决定名字，全机房同名、可预测 | 高 |
| **反复复活同伙** | 3 秒一轮把 `jfglzsn` 拉起来，`.dat` 被删还能从 `C:\windows\jf\` 重新释放；杀 40 次才报警 | 高 |
| **删除用户文件** | 监视下载、桌面（含子目录）、我的文档、**每个盘符根目录**与两个"360浏览器下载"目录；`.exe/.com/.reg/.bat/.cmd/.vbs/.vbe/.scr/.dll/.ps1/.pif/.msi` 一律删，改名的 PE 也认 `MZ` 头删掉；重命名成 16 种危险扩展名同样删 | 高 |
| **锁屏与强制重启** | 阈值触发后全屏置顶、鼠标被 `ClipCursor` 锁在左上角、蜂鸣、关不掉；提供 `shutdown /r /f /t 0` 一键强制重启 | 高 |
| **策略篡改（系统级）** | 四个 ControlSet 写 `usbstor\Start=4` 禁 U 盘；12 个策略值禁下载/另存为/开发者工具；2 个值关游戏彩蛋 | 高 |
| **破坏用户会话** | 发现策略被改就杀 `chrome`/`msedge`/`firefox`/`iexplorer`/`explorer`，再重启 `explorer`——正在编辑/浏览的内容全部丢失 | 中 |
| **hosts 守护** | 15 秒一轮，删了就从 `hosts2` 恢复；`hosts2` 也不在就锁屏 | 中 |
| **隐藏后门** | 看不见的标签双击 → 泄露带机器码的暗号、把明文密码写注册表、写入默认口令摘要、启动 `yz.exe` | 中 |
| **密码体系可破** | 单轮 `SHA256(明文 + 固定盐 "bfdshgs")`，盐硬编码、无迭代、无 HMAC，可离线爆破；后门还留了 `111111` 一档 | 中 |
| **反分析** | `[SuppressIldasm]`、程序集作者字段全空、`.NET Reactor + IntelliLock` 双层壳、壳运行时含 `VirtualProtect` + `WriteProcessMemory` 的自修改代码 | 中 |

**这套组件的真正定位**：它不是"管理工具"，而是**一个没有开关的强制器**——所有开关（`xiazai`、`gaowei`、
`usb_jianche`、`games_jianche`、`bianhao`）都掌握在管理员侧组件手里，学生侧只有"被删文件 + 被锁屏 +
被强制重启"三种反馈，且 `Form2` / `Form3` 的文案本身就在暗示"再次操作会锁屏"。

**本工程的行为边界（同样值得记录）**：

- **不联网**：没有任何 HTTP/Socket 调用，所有策略值都从本地注册表读；
- **Form4 在本工程内是死代码**：没有 `Show()`、`Proccesor.锁屏中禁止关闭` 也没人置 `true`，
  "双锁屏"实际只有 Form2 一把生效；`Timer4` 同样是创建后永不启用的空壳；
- **`高危文件删除计数` 只累加、没有任何阈值判定**，`_Reponse`、`worker`、`_Attribute`、
  `_Container`、`token`、`_Map`、`m_Setter` 等字段全工程零读写；
- **退出 ≠ 卸载**：密码只能让 przs 自己停下来，迁居副本、`prozs` 自启动项、已写入的策略一个都不清，
  下次开机照样运行——真正的清理必须走 `uninstall.exe` 那条受控通道。

> 处置提醒（基于本工程的代码顺序）：它自己的退出流程就是「先 `net stop zmserv` → 等 3 秒 → 再杀 `zmserv`」，
> 手工处置照这个顺序做更稳；最后别忘了清掉 `C:\Program Files (x86)` 下的随机副本和 `HKLM\…\Run` 的 `prozs`，
> 否则 3 秒一轮的看护逻辑与下次开机会把它再拉回来。
